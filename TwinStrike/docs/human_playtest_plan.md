# 喵拳道場 真人試玩計畫（路線 A 第 1 階段）

> 目的：確認 bot 推估的難度、手感、延遲校正在真人身上成立，再決定要不要調整判定窗、腳本與新手引導，最後才進後端開發。
> 對應：[launch_checklist.md](launch_checklist.md) §1.1–1.6；自動化預測見 [playtest_report.md](playtest_report.md)。

## 1. 要驗證的假設與通過標準

| # | 假設 | 量法 | 通過標準 |
|---|---|---|---|
| H1 | 一般玩家能打完全場 | 一般組最佳局 | 打完比例 ≥ 70% |
| H2 | 新手大約在一分鐘倒下，不會太早挫折 | 新手組第一局倒下時間 | 中位數 45–70 秒；30 秒內倒下 ≤ 20% |
| H3 | 技巧有天花板、練習會進步 | 同一人第 3 局 vs 第 1 局分數 | 中位數進步 ≥ 10% |
| H4 | bot 模型能代表真人 | `human-report` 的「模型偏差」 | 沒有任何段落差 > 10 pp（有就回頭調 `tools/humanBots.mjs`） |
| H5 | 延遲校正可用 | 校正值與重做次數 | 90% 的人一次成功；數值都在 ±150 ms 內 |
| H6 | 好玩、公平、想再玩 | 問卷（1–5 分） | 難度 2.5–3.5、公平感 ≥ 4、想再玩 ≥ 3.5 |
| H7 | 沒有卡關級問題 | 觀察紀錄 | 無當機、無音訊失效、無無法點擊 |

## 2. 招募（20 人）

| 組別 | 人數 | 條件 |
|---|---|---|
| 新手 | 8 | 平常玩手機休閒遊戲，沒玩過節奏遊戲 |
| 一般 | 8 | 有玩手遊習慣，玩過一兩款節奏或動作遊戲 |
| 熟手 | 4 | 常玩節奏遊戲（太鼓、Cytus、DJMAX 等） |

裝置：iPhone ≥ 8 台、Android ≥ 8 台；至少 5 人戴藍牙耳機、5 人用外放。每人分配一個代號（例如 N01、R01、S01），不收集真實姓名。

## 3. 開放試玩網址

同一個 Wi-Fi 下用電腦開伺服器（或部署到任何靜態網站）：

```bash
npm --prefix TwinStrike/game run build
```

```bash
npm --prefix TwinStrike/game run preview -- --host --port 5175
```

試玩者開啟：`http://<電腦 IP>:5175/?playtest=1&tester=<代號>&seed=1234`

- `playtest=1&tester=` 會把每局完整的輸入紀錄存在手機上；結算畫面出現「匯出試玩紀錄」按鈕。
- `seed=1234` 讓所有人打同一份題目，結果才能比較。

## 4. 每人流程（約 20 分鐘）

1. **說明（1 分鐘）**：只講「敵人踏進框時點那一邊」，其他讓遊戲自己教。不要示範。
2. **延遲校正（1 分鐘）**：標題畫面按「延遲校正」完成兩輪。記下是否重做。
3. **正式打 3 局**：同一份題目，局與局之間不給建議。觀察員記錄「第幾秒、發生什麼、玩家反應」。
4. **問卷（3 分鐘）**：見 §5。
5. **匯出**：結算畫面按「匯出試玩紀錄」，把下載的 JSON 用 LINE 或 email 傳回；觀察員確認檔名有代號。

## 5. 問卷

1–5 分（1 = 非常不同意，5 = 非常同意；難度題 3 = 剛好）：

| # | 題目 |
|---|---|
| Q1 | 難度：1 太簡單 … 3 剛好 … 5 太難 |
| Q2 | 輸贏取決於我的技巧，不是運氣（公平感） |
| Q3 | 打中時很爽（打擊感） |
| Q4 | 音樂和打擊聲讓我更容易抓到節奏 |
| Q5 | 狸貓頭目的大箭頭提示很清楚 |
| Q6 | 失敗時我知道自己哪裡做錯 |
| Q7 | 我想再玩一次 |

開放題：最喜歡的瞬間？最挫折的瞬間（第幾秒、什麼情況）？有沒有看不懂的地方？

## 6. 觀察紀錄欄位

| 欄位 | 範例 |
|---|---|
| 代號 / 組別 / 裝置 / 耳機 | R03 / 一般 / Pixel 8 / 藍牙 |
| 時間點（秒） | 57 |
| 事件 | 第一次遇到狸貓、連續空揮、被打到、停頓、笑、皺眉 |
| 玩家原話 | 「箭頭是要點哪邊？」 |

## 7. 分析

把所有 JSON 放進同一個資料夾（例如 `TwinStrike/playtest-data/`）：

```bash
node TwinStrike/game/tools/human-report.mjs TwinStrike/playtest-data --out TwinStrike/docs/human_playtest_report.md
```

- 每一局都用伺服器同一份 sim 重播驗證；被竄改或版本不符的紀錄會列在「剔除」。
- 報告列出：打完比例、倒下時間、Perfect 率、學習曲線、各段命中率對照三種 bot 模型、每位試玩者最像哪個模型、延遲校正分布。
- **注意**：試玩期間不要改 sim（`GAME.version` 一變，舊紀錄就無法重播分析）。

## 8. 結果怎麼用

| 結果 | 調整方向 |
|---|---|
| H1 未過（一般玩家打不完） | 先看倒在哪一段：調該段腳本的難度級或拍速；必要時 HP 6 → 7 |
| H2 太早倒下 | 暖身、起手多一小節；交鋒延後出疾兵；回血門檻 12 → 10 |
| H2 太晚倒下（太簡單） | 收緊判定窗（Good 135 → 120 ms）或提早 L7 |
| H3 沒進步 | 檢查是不是運氣主導（分數差異大但無規律）→ 看樂句與種子 |
| H4 模型偏差 | 依偏差段落調 `humanBots.mjs`（換邊、新敵人、密度係數），重跑 `npm run playtest` |
| H5 校正失敗多 | 預備拍加長、改用更明顯的閃光或音色 |
| Q5 低 | 頭目箭頭放大、延長登場預告 |
| Q4 低 | 調 BGM 音量、keysound 音色；查延遲校正值是否偏大 |

每次調整都要重跑 `npm test`、`npm run playtest`，sim 版本 +1；若要和舊試玩資料比較，請在調整前先產出報告。
