# 16 難度曲線設計與驗收規範

> 補 [09](09_knowledge-gaps.md) G5。把「怎麼設計難度曲線」和「怎麼證明曲線是對的」綁成一套流程：**曲線用腳本設計、用自動化試玩驗收、用固定門檻判定**。
> 實作範例：TwinStrike（喵拳道場）—— 設計 [gdd/07_difficulty_curve.md](../TwinStrike/gdd/07_difficulty_curve.md)，工具 `game/tools/humanBots.mjs`（`TwinStrike/game/tools/humanBots.mjs`，未收錄）、`difficulty-curve.mjs`（`TwinStrike/game/tools/difficulty-curve.mjs`，未收錄）、`playtest.mjs`（`TwinStrike/game/tools/playtest.mjs`，未收錄），最新報告 docs/playtest_report.html（`TwinStrike/docs/playtest_report.html`，未收錄）。新遊戲起手：範本已附 `tools/humanBots.mjs`、`tools/playtest.mjs`（示範遊戲 Beat Tap 的單位與 DI）與通用檢查 `tools/lib/curve.mjs`，`npm run playtest` 即跑。
> 與其他頁的關係：公平性門檻見 [01](01_skill-integrity.md) §4；節奏 / 物理的 sim 配方見 [12](12_genre-recipes.md)；輸入延遲見 [13](13_input-fairness.md)。

## 1. 核心觀念：設計和驗收是同一件事的兩面
<!-- card: KB-difficulty-curve.core-idea; kind=principle -->

| | 設計（寫進 sim 的腳本） | 驗收（自動化試玩量出來的） |
|---|---|---|
| 難度往上走 | 固定腳本：段落、拍速、每小節難度級 | 逐小節難度指數（DI）的趨勢與線性擬合 |
| 一次只教一件事 | 難度級 L1 → Ln，每級只加一個新要素 | 新要素第一次出現的那段，命中率不能斷崖 |
| 有張有弛 | 上升鋸齒：堆高 → 高峰 → 調息 → 更高 | 各段高峰遞增；調息段 DI 明顯回落 |
| 不同玩家有不同終點 | 容錯參數（血量、保護期、回血） | 人性化 bot 的存活曲線、倒下時間 |
| 技巧決定結果 | 只有種子決定內容；腳本固定 | 技巧主導 ≥ 70%（[01](01_skill-integrity.md) §4） |

**規則：曲線的形狀由腳本決定，不由隨機決定。** 種子只能在「同一難度級」裡換內容（樂句、鏡像），所以每個種子的難度形狀一樣，跨日排行才公平。

## 2. 設計規範
<!-- card: KB-difficulty-curve.design-rules -->

### 2.1 腳本化（不要用權重隨機出題）

| 要素 | 規範 | 喵拳道場的做法 |
|---|---|---|
| 單位 | 以「一個可讀的小段」為單位：節奏類 = 1 小節；動作類 = 一波；解謎類 = 一題 | 1 小節 = 8 個八分音，用字串寫：`A.B.a...` |
| 難度級 | 6–10 級；每升一級只加**一個**新要素（教 → 測 → 混） | L1 單邊 → L2 換邊 → L3 八分音二連 → L4 疾兵 → L5 兩側疾兵 → L6 快速換邊 → L7 混合 → L8 高密度 |
| 新要素登場 | 第一次出現時前後留空、單獨出現 | 疾兵登場的樂句前後都是休止 |
| 種子的作用 | 只在同級樂句中挑選、左右鏡像 | `pattern` / `lane` 兩個 stream，依小節序號取值 |
| 段落長度 | 主段落用 4 或 8 個單位（音樂上的完整樂句） | 起手 4、交鋒 8、激戰 8、猛攻 4、決戰 8 小節 |
| 拍速 / 速度 | 逐段上升，不要跳級暴衝 | 112 → 120 → 129 → 144 → 157 → 171 BPM |
| 頭目 / 特殊敵 | 放在段落結尾，**獨占**那一段，間隔加寬，懲罰設上限 | 狸貓頭目：小節末、四分拍、每場最多扣 1 血 |

### 2.2 曲線形狀：上升鋸齒

喵拳道場 v5 的實測（每段平均 / 高峰 DI）：

| 暖身 | 起手 | 調息 | 交鋒 | 無雙 I | 調息 | 激戰 | 猛攻 | 無雙 II | 調息 | 決戰 | 收尾 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1.3 / 1.9 | 2.0 / 2.0 | 0.8 | 1.9 / 2.1 | 3.0 / 3.8 | 2.3 | 3.3 / 3.9 | 4.3 / 6.3 | 4.2 / 4.5 | 2.8 | 5.9 / 7.2 | 1.8 |

- 每個主段落：開頭比上一段高峰略低（喘口氣），結尾是新高峰。
- 段落之間插入**調息**（1 小節低密度、可回 1 血），給玩家釋放壓力的空間。
- **無雙段 / 安全段**：高密度但不扣血，讓玩家在沒有壓力的情況下先練下一級的技巧。

### 2.3 容錯參數（決定「誰在哪裡倒下」）

| 參數 | 作用 | 喵拳道場 v5 |
|---|---|---|
| 判定窗 | 越寬越好打；改了要同步改結算畫面 | ±45 / ±85 / ±135 ms |
| 失誤硬直 | 防狂按；太長會連鎖失誤 | 200 ms |
| 血量 / 回血 | 決定新手能撐多久 | 6 血；每 12 連擊回 1；調息段回 1 |
| 保護期 | 一次失誤常連帶漏 1–2 下，合併成一次傷害 | 扣血後 0.5 s 不再扣 |
| 頭目懲罰上限 | 避免單一難點直接結束遊戲 | 每場頭目最多扣 1 血 |

> 經驗：放寬容錯**不會**降低技巧主導，反而會提高（喵拳道場 v1 → v2：90% → 98%）。因為中手不再中途倒下，分數差異回到「打得準不準」，而不是「死得早不早」。

## 3. 驗收：人性化自動試玩
<!-- card: KB-difficulty-curve.humanized-playtest; topic=difficulty,fairness -->

### 3.1 為什麼不能只用技巧等級 bot

技巧等級 bot（[01](01_skill-integrity.md) §4）只有「準 / 不準」，證明的是**公平**。曲線要的是**人會在哪裡卡住**，所以要用模擬人類失誤原因的 bot：

| 因素 | 模型 | 對應的設計問題 |
|---|---|---|
| 讀取負荷 | ±0.5 s 內敵人越多，誤差越大 | 密度是否超出人類負荷 |
| 快速換邊 | 與前一個不同側且間隔 < 0.3 s：誤差變大、點錯邊機率上升 | 換邊樂句太密 |
| 新要素 | 第一次看到新敵人誤差大，約 6 次後學會 | 新要素登場是否有足夠緩衝 |
| 反應時間 | 預告時間 < 反應時間 → 只能晚點或漏掉 | 預告時間是否太短 |
| 急躁 | 偶爾提早出手 | 硬直懲罰是否過重 |
| 疲勞 | 60 秒後誤差略升 | 後段難度是否疊加過度 |

三位玩家：**新手**（σ 約 58 ms、反應 320 ms）、**一般**（34 ms / 250 ms）、**熟手**（20 ms / 200 ms）。參數放在 `humanBots.mjs`，有真人資料後要校正。

### 3.2 量測項目（逐小節 / 逐段）

| 類別 | 指標 |
|---|---|
| 負荷 | notes/s、快速換邊比例、特殊敵比例、難度指數 **DI = notes/s × (1 + 0.5 × 換邊) × (1 + 0.3 × 疾兵 + 0.2 × 頭目)** |
| 玩家 | 三位玩家的命中率、Perfect 率、存活率、血量、新手中位倒下時間 |
| 曲線 | 主段落 DI 對時間的線性擬合（斜率、R²）、Spearman ρ、偏離擬合線 2σ 的尖峰 / 凹陷 |
| 節奏 | 所有目標是否在拍格上；反拍比例、切分比例隨段落的變化 |
| 樂句 | 主段落長度是否為 4 的倍數 |
| 旋律（有 keysound 時） | 每小節音域、最大跳進 |

> DI 的權重是喵拳道場的起手值；換品類時改成該品類的負荷來源（見 §6），並用人性化 bot 的命中率回頭校正：DI 越高，命中率應該越低（相關係數為負且明顯）。

## 4. 驗收門檻（任一不過 → exit 1，不能上線）
<!-- card: KB-difficulty-curve.gates; rules=RULE-CURVE-TREND,RULE-CURVE-LINEARITY,RULE-CURVE-PEAKS,RULE-CURVE-CLIFF,RULE-CURVE-FLOW,RULE-CURVE-BEATGRID,RULE-CURVE-PHRASE -->

| # | 檢查 | 門檻 | 失敗時通常怎麼改 |
|---|---|---|---|
| D1 | 技巧主導 | 技巧佔比 ≥ 70%、最強 vs 次強 ≥ 70% | 拿掉非線性加成、加長局長（[12](12_genre-recipes.md) §3） |
| D2 | 難度整體上升 | 主段落逐單位 Spearman ρ ≥ 0.6 | 檢查是否有段落比前一段簡單 |
| D3 | 難度接近線性 | 主段落 R² ≥ 0.5 | 前段太平就提早引入新要素；後段暴衝就把高難度級提前分攤 |
| D4 | 鋸齒向上 | 每個主段落的高峰 ≥ 前一段 | 調整段末的難度級 |
| D5 | 無斷崖 | 一般玩家相鄰主段落命中率下降 ≤ 12 個百分點 | 新要素前後留空、降一級、或拆成兩段 |
| D6 | 心流帶 | 一般玩家主段落命中率落在 90–99% | 太高 → 加速或提級；太低 → 放寬容錯 |
| D7 | 拍格 | 所有目標都在節拍 / 分拍上（節奏類） | 樂句只用合法的格位 |
| D8 | 樂句長度 | 主段落長度為 4 的倍數 | 重排段落 |

**目標值（不做硬門檻，報告裡要寫）**：新手中位倒下時間落在全長的 55–80%（喵拳道場：58 / 85 秒）；一般玩家全部打完；熟手命中率 ≥ 95%。

## 5. 調校流程
<!-- card: KB-difficulty-curve.tuning -->

```
腳本 / 容錯參數 ──▶ npm test（確定性、golden）──▶ npm run playtest ──▶ 讀報告
      ▲                                                               │
      └──────────── 依 §4「失敗時怎麼改」調整，改到結果就 GAME.version +1 ◀┘
```

1. 改腳本或容錯參數之前，先跑一次 `npm run playtest` 留下基準。
2. 一次只改一類東西（腳本 **或** 容錯），否則看不出是哪個改動造成的。
3. 會影響結果的改動：`GAME.version` +1、更新 golden match、重新產生三份報告（skill-dominance / difficulty-curve / playtest）。
4. 調校紀錄寫進該遊戲的 `gdd/07`：每一版改了什麼、結果數字（喵拳道場 r1 → r3、v4 → v5 的表格可以照抄格式）。
5. 有真人試玩資料後：用真人命中率校正 `humanBots.mjs` 的參數，再重跑一次。

### 喵拳道場的調校實例

| 發現 | 原因 | 改法 | 結果 |
|---|---|---|---|
| 新手 11 秒就倒下 | 暖身段就會扣血 | 暖身改安全段 | 撐到 24 秒 |
| 第二次無雙段 DI 4.6 → 7.6 | 高難度級和最快拍速擠在一起 | 降一級並放慢 | 曲線平順 |
| 狸貓太難、很快就死 | 八分音三連打 + 換邊 + 每下扣血 | 改成段末頭目、四分拍、最多扣 1 血 | 新手撐過激戰 80% → 90% |
| 6 小節段落聽起來少半句 | 主段落不是 4 的倍數 | 改成 4 / 8 小節 | D8 通過 |
| 起手到交鋒持平、決戰暴衝 | 高難度級全擠在最後 | 高難度級提前一段分攤 | R² 0.66 → 0.69，無尖峰 |

## 6. 套用到其他品類
<!-- card: KB-difficulty-curve.other-genres -->

| 品類 | 「單位」 | DI 的負荷來源（取代 notes/s × 換邊） | 新要素範例 |
|---|---|---|---|
| 節奏 / 左右打怪（OFDP、Timberman） | 小節 | 密度、換邊、預告時間 | 疾兵、頭目、多擊敵 |
| 撞球 / 泡泡龍 | 一局或一題的球型 | 進袋線數、需要的薄切角度、連續解題步數 | 隔球、組合球 |
| 塔防 | 一波 | 每秒到達敵人 HP、路線數、特殊敵比例 | 飛行、隱形、分裂 |
| 走位 / 生存（SwarmDuel 類） | 30 秒區間 | 同屏威脅數、彈幕密度、安全區面積 | 新武器、頭目 |
| 三消 / 規劃 | 一盤 | 有效步數比例、必要連鎖深度 | 障礙格、限步 |

不論哪個品類，§4 的 D1–D6 都適用；D7–D8 只用於有節拍的品類。
