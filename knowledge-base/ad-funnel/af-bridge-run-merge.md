# 疊磚過橋 + 合成跑酷（Bridge Run / Stack-and-Merge Runner：Last War 2026 代理素材）

- **代號**：af-bridge-run-merge
- **類別**：跑酷 / 4X 代理小遊戲（收集堆疊 → 建橋 / 推障礙 → 合成升級）
- **代表作 / 廠商**：Last War: Survival — FirstFun（2026 年代理素材主力之一）；超休閒原型：Bridge Race（Supersonic，2021，未證實）、各類 stack runner（未逐一證實）；*Those Games* 的「Cash Run」模式（收集鈔票堆疊當積木過障礙，Monkey Craft / D3 Publisher 2023）
- **投放熱度依據**：
  - AppGrowing 抽樣 2026-06-16～07-16 的 157+ 支 Last War 素材：**至少 30 支是過橋 / 跑酷式代理玩法**，其他代理動作包括推障礙與合成；結構為「受阻 → 低摩擦衝突 → 可見進度 → 軍隊 / 資源 / 基地規模的成長回報」（[AppGrowing 2026-07-16](https://appgrowing.net/blog/en/how-last-war-uses-proxy-minigames-to-package-strategy-gameplay/)）。**這是本批格式中最新（2026 年中）的實測熱度證據。**
  - Gamigion：Last War 的 TikTok 廣告呈現「合成 + 奔跑」的快節奏玩法，開場數分鐘與廣告一致，之後合成機制保留為小遊戲（[Gamigion](https://www.gamigion.com/?p=24490)）。
  - Last War 素材的流量來源中出現 Zombie Waves、Block Blast 等休閒遊戲作為投放版位（Insightrackr 2026-04）。
  - 台灣：未取得此格式台灣占比；Last War 整體將台灣列為高成長投放市場（Insightrackr，台灣/中國併列 3.43%）。
- **廣告真實度**：**部分真實**（開場有，之後轉 4X；AppGrowing 明言計數只能證明素材家族存在，不能證明哪一家族轉換較好）。
- **技巧 vs 選擇 vs 運氣**：原型（Bridge Race 類）有真實走位與搶資源技巧；4X 代理版多為「看起來在跑」的進度演出，技巧低。

## 一句話玩法

沿路收集同色磚塊疊在背上，用磚鋪橋跨過斷崖，抵達後合成升級部隊。

## 為什麼廣告有效（Hook）

| 元素 | 說明 |
|---|---|
| 前 3 秒畫面 | 角色背著一疊磚衝向斷崖，橋只鋪到一半——「夠不夠？」的懸念（AppGrowing 所說的「失敗或受阻」開場）。 |
| 失敗誘導（fail bait） | 磚不夠、橋差一格掉下去；或推障礙推錯方向卡死。 |
| 「我來一定行」的錯誤示範 | 示範者明顯漏撿旁邊的磚堆，觀眾覺得自己會走更好的路線。 |
| 爽感 / 解壓點 | 背上磚塊越疊越高（堆疊 ASMR）、橋一格格延伸、抵達後兩個小兵合成大兵的「升級」閃光。 |

## 遊戲規格

> 以下為本工作室規格「建議值」；Last War 代理版實際數值未取得（未證實）。

### 核心循環
1. 區段 A（收集）：場地散布磚塊（己方色）與干擾物；角色經過即自動撿起，背上堆疊數 S。
2. 區段 B（建橋）：走上斷崖，每前進 1 格消耗 1 磚；S 用完則停在橋端（多人版會掉落）。
3. 區段 C（推 / 合成）：抵達平台，用剩餘磚換兵；同級兩兵合成高一級（2048 式）。
4. 終點：部隊戰力與敵方比較或對撞。

### 規則與勝負
- 橋長 L 由關卡決定；S ≥ L 才能過；剩餘 S − L 進入合成階段。
- 撞到障礙物（擺錘、滾桶）掉落 30% 磚（建議）。
- 多人（Bridge Race 原型）：對手撞到你會撞掉你的磚；不同顏色的磚只能由同色玩家撿。

### 操作
- 浮動搖桿自由移動（Bridge Race 型）；或單指左右（跑道型）。

### 關卡結構與難度曲線
| 關卡段 | 新元素 | 難度槓桿 |
|---|---|---|
| 1–5 | 單橋、磚量充足 | 學會「先撿再上橋」 |
| 6–15 | 雙橋（短橋需較少磚但有障礙） | 路線選擇 |
| 16–30 | 對手 AI 搶磚、撞人 | 時間壓力 + 衝突 |
| 30+ | 多段橋、合成門檻 | 資源分配（多少磚建橋、多少留合成）|

### 計分 / 星等 / 獎勵
- 原型：名次（先到終點）；4X 代理版：抵達後給部隊 / 資源。

### 失敗與轉換點（廣告續命、IAP、導流到主遊戲的位置）
- 4X 代理版：數關後「部隊」直接帶入主城系統 → 轉入 4X（AppGrowing 描述的「軍隊 / 資源 / 基地規模回報」）。
- AppGrowing 建議 CTA 延續開場的同一承諾，不要用泛用的「立即下載」。

## 可玩廣告（Playable Ad）結構

- 建議 20–25 秒：收集 8 秒 → 建橋 5 秒（故意讓磚剛好差 1–2 格，逼玩家回頭撿）→ 合成 1 次 → CTA。
- 結束畫面：合成後的大兵 + 「你的部隊等你指揮」式文案（與主遊戲承諾一致）。

## 技巧要素

| 技巧 | 影響 |
|---|---|
| 收集路線 | 單位時間撿磚效率 |
| 何時上橋 | 磚夠就上 vs 多撿一點保險（風險換時間）|
| 閃避 / 碰撞 | 擺錘、對手撞擊 |
| 資源分配 | 多留磚 → 合成更強，但更晚抵達 |

## 隨機 / 選擇噱頭

- 原型：磚塊重生位置隨機（未證實）→ 運氣影響收集量。
- 4X 代理版：大部分是演出，結果與玩家輸入關聯弱。

## Skill Game 化改造（必做）

> 用這份規格書做遊戲時（含「復刻」），玩法規格 `gdd/05_game_spec.md` §13 要逐條回應下列每一條：採用就寫本作做法，不採用就寫理由與替代做法。「復刻」只復刻玩法結構與操作，不跳過本節（`RULE-AF-ADAPTATION`，`npm run audit` 檢查）。

1. **磚塊重生確定性**：每個磚位的重生時間表 = `rng(seed,"brick",slot,n)`；雙方完全相同。
2. **風險換時間**：橋格可以「跳過」——在橋端按跳躍（磚 ≥ 2 時消耗 2 磚越過 1 格缺口，建議）；失手掉落損失全部磚並回到該段起點。
3. **合成是時間壓力下的 2048**：抵達合成台後有 10 秒，以滑動合併小兵，最高等級兵 × 剩餘時間計分。
4. **計分公式（建議）**：`Score = 抵達時間獎勵 (60 − 秒數) × 10 + 合成最高等級 × 50 + 剩餘磚 × 2 − 掉落次數 × 20`。
5. **同步對戰**：最多 4 人同場搶磚（同色規則避免直接搶走，但可撞人）；撞人判定以 sim tick 決定，延遲以時間戳輸入補償（見 13_input-fairness）。
6. **局長**：3 段 × 25 秒 + 合成 10 秒 ≈ 85 秒。

## HTML5 輕量實作規格

| 項目 | 規格 |
|---|---|
| 畫面 | 直版 720×1280；斜俯視 2.5D（Y 排序）或 3D 低多邊形 |
| 實體與資料結構 | 玩家 ≤ 4 `{x,y,stack,color,stunTicks}`；磚位 ≤ 120 `{x,y,respawnAt}`；橋 `{segments[], filled[]}`；障礙 ≤ 10；合成格 4×4 `Uint8Array` |
| 關鍵參數 | 移速 240 px/s；撿磚半徑 24 px；背上堆疊顯示上限 40（超過只顯示數字）；建橋 1 格 / 6 tick；撞擊掉落 30%；跳躍消耗 2 磚 |
| 渲染 / Draw Call 估計 | 地面 1；角色 + 磚 + 橋 + 障礙同 atlas 1（背上堆疊 40 個 sprite 合批）；BitmapText 1；合成 UI 可用 DOM → **3 DC**。3D 版：地形 1、磚 instancing 1、角色 1、橋 instancing 1、障礙 1 → **5 DC** |
| 美術資產清單 | 角色 4 色 × 跑 4 幀；磚 4 色（同一 sprite + tint）；橋段 1；擺錘 / 滾桶 2；兵 5 級圖示；地形 1 張 |
| 包體估計 | 程式 0.9 MB；atlas 0.35 MB；音效 0.25 MB；BGM 1.5 MB → **≈ 3 MB** |

## 主題與美術風格

- Last War 版：軍事 + 殭屍；Bridge Race 型：糖果色極簡；*Those Games* Cash Run：鈔票堆疊（博弈 / 金錢視覺，**不要學**）。
- 改造：積木、冰塊、蜂巢片等中性材料。

## 可借用 / 要避開

- **可借用**：堆疊高度即時可見的資源感；「差一格」懸念；多人同色搶資源的低衝突 PvP。
- **要避開**：鈔票 / 金幣當堆疊物；與本體不符的代理玩法廣告（見 [_notes-runner-fake-ads](_notes-runner-fake-ads.md) 法規段）。
