## 一句話玩法

在暴風雪中奔走砍柴、搬運、添火，在倖存者凍死前讓暖爐與庇護所運轉起來。

## 為什麼廣告有效（Hook）

| 元素 | 說明 |
|---|---|
| 前 3 秒畫面 | 倖存者縮在雪地發抖、頭上體溫條快見底；或瘟疫醫生 + 綠色藥水（Last Asylum）。「角色受難」激發同理與緊迫感（Segwise）。 |
| 失敗誘導（fail bait） | 示範者先去蓋裝飾而不是添柴 → 倖存者一個個凍僵；或藥水配錯。 |
| 「我來一定行」的錯誤示範 | 優先順序（先救命再建設）明顯，觀眾覺得自己會排得更好。 |
| 爽感 / 解壓點 | 進度條填滿、資源堆疊、庇護所從破屋變溫暖城鎮的前後對比（「Progress Bar Elements」標籤）。 |

## 遊戲規格

> 以下為本工作室規格「建議值」；原作機制細節未取得者標（未證實）。

### 核心循環
1. 玩家角色在小地圖上移動，靠近資源點（樹、礦）自動採集，背上堆疊（容量上限）。
2. 走到工作站（暖爐、廚房、醫療站）自動卸貨 → 站點運轉產出（熱、食物、藥）。
3. 倖存者有體溫 / 飢餓 / 病況條隨時間下降；獲得對應產出則回升。
4. 賺到的本局貨幣解鎖新站點 / 擴大容量 / 雇用自動搬運工。
5. 撐過「第 N 夜」或救活全部倖存者 → 結算；原作轉入 4X 主城。

### 規則與勝負
- 任一倖存者狀態條歸 0 = 倒下（扣分或失敗，視模式）。
- 暴風雪事件：週期性降溫加速（例：每 45 s 一次、持續 10 s，建議）。

### 操作
- 浮動搖桿單指移動；採集、卸貨全自動（idle arcade 慣例）。

### 關卡結構與難度曲線
| 關卡段 | 新元素 | 難度槓桿 |
|---|---|---|
| 0–30 s | 1 個暖爐、2 名倖存者、樹 | 學會「砍 → 搬 → 添」 |
| 30–90 s | 廚房（食物條）、第 3–4 名倖存者 | 兩條需求並行，路線取捨 |
| 90–150 s | 暴風雪、傷病（醫療站）| 突發需求排序 |
| 150 s+ | 自動搬運工解鎖 | 投資 vs 立即救援 |

### 計分 / 星等 / 獎勵
- 原作：完成新手段進入主城；無明確分數（未證實）。

### 失敗與轉換點（廣告續命、IAP、導流到主遊戲的位置）
- 原作前期即為 4X 主體的一部分；搬運經營逐步被建築排隊、加速道具（付費）取代（未證實細節）。
- 「no ads」素材與真人短劇是此類 4X 另一主力（Kingshot / Dark War 數據）。

## 可玩廣告（Playable Ad）結構

- 建議 25 秒：倖存者體溫條閃紅 → 玩家拖曳去砍柴（5 s）→ 搬到暖爐（5 s）→ 火燃起、體溫回升 → 第二名倖存者倒下的同時 CTA（製造「還沒救完」的未完成感）。
- Whiteout 素材以影片為主（Insightrackr 指約 84%，未逐一證實），playable 細節未證實。

## 技巧要素

| 技巧 | 影響 |
|---|---|
| 路線規劃 | 一趟背滿再送 vs 少量快送 |
| 需求排序 | 誰先救、哪條先補 |
| 投資時機 | 何時花錢雇搬運工 / 擴容 |
| 事件預判 | 暴風雪前先囤柴 |

## 隨機 / 選擇噱頭

- 原作經營段幾乎無隨機；「求救」主要是情緒演出，不是難題。
- 真正的勝負槓桿（建築速度）在 4X 段由付費加速決定。

## Skill Game 化改造（必做）

> 用這份規格書做遊戲時（含「復刻」），玩法規格 `gdd/05_game_spec.md` §13 要逐條回應下列每一條：採用就寫本作做法，不採用就寫理由與替代做法。「復刻」只復刻玩法結構與操作，不跳過本節（`RULE-AF-ADAPTATION`，`npm run audit` 檢查）。

1. **把 idle 變成「搬運最佳化」動作題**：地圖固定、需求曲線由種子決定；倖存者狀態條同時下降，玩家要即時規劃路線（類似 Overcooked 的單人版）。
2. **容量與速度取捨**：背得越多走越慢（每多 5 個 −8% 速，建議）→ 「一趟滿載」不一定最優。
3. **同種子**：暴風雪時刻、倖存者需求變化、資源點重生 = `rng(seed,"event",i)`；雙方相同；無局外建築等級。
4. **計分公式（建議）**：`Score = Σ(每名倖存者每秒的狀態值 / 100) + 救援完成數 × 50 − 倒下數 × 100`；即「平均照護品質 × 時間」，獎勵穩定維持而非臨時救火。
5. **局長**：180 秒（3 夜）；非同步排行榜。
6. **移除**：自動搬運工的付費加速、看廣告加倍產出、離線收益（idle 的「不玩也成長」與技巧主導衝突）。

## HTML5 輕量實作規格

| 項目 | 規格 |
|---|---|
| 畫面 | 直版 720×1280；斜俯視 2.5D 單畫面小鎮（不捲動，公平視野）|
| 實體與資料結構 | 玩家 `{x,y,carry[type],cap}`；資源點 ≤ 16 `{type,x,y,hp,respawnAt}`；工作站 ≤ 6 `{type,buffer,rate}`；倖存者 ≤ 8 `{temp,food,health}`（整數 0–1000）；搬運工 ≤ 3（固定路線 AI）|
| 關鍵參數 | 移速 220 px/s（滿載 −8%/5 件）；容量 10–30；體溫下降 6/s、暴風雪 ×2.5；暖爐每柴 +40 熱、熱量平均分給半徑 200 px 內倖存者 |
| 渲染 / Draw Call 估計 | 地面（雪地 1 張）1；角色 + 建築 + 資源 + 倖存者同 atlas 1；背上堆疊（同 atlas）併入；雪花用 1 個 `ParticleContainer`（同 texture）1；狀態條 / 數字 BitmapText 1 → **4 DC**。暖爐光暈用預烘焙 sprite（加色），不用 filter |
| 美術資產清單 | 主角 4 向 × 4 幀、倖存者 3 狀態（冷 / 正常 / 倒下）、建築 6 種 × 2 級、資源 3 種、雪花 1、光暈 1、地面 1（WebP）|
| 包體估計 | 程式 0.9 MB；atlas 0.6 MB；地面 0.2 MB；音效 0.3 MB；BGM 1.5 MB → **≈ 3.5 MB** |

## 主題與美術風格

- 原作：冰原末日（Whiteout）、末日避難所（Dark War）、瘟疫醫院（Last Asylum）——偏沉重。
- 改造：可輕量化為「冬眠前的松鼠村」「颱風天的漁港」等台灣在地題材；避免病患 / 屍體寫實。

## 可借用 / 要避開

- **可借用**：「角色受難 + 進度條」雙標籤組合（Segwise）作為我們實機素材的開場；idle arcade 的零學習門檻；照護品質型計分。
- **要避開**：離線收益、付費加速、自動化取代操作；求救演出與實機不符（ASA 對「核心玩法不符」的一貫立場）。
