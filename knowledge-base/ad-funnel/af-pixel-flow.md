# 輸送帶射色清圖（Pixel Flow!）

- **代號**：af-pixel-flow
- **類別**：解謎排序 → 顏色射擊排序（Color Shooter / Sorting Shooter；AppMagic 歸在 Sort Puzzle）
- **代表作 / 廠商**：Pixel Flow! — Loom Games（伊斯坦堡，2025-08 上線；Deconstructor of Fun 記為 8 月 17 日）。2026-02 Scopely 取得多數股權，估值逾 $1B。仿作：Color Pixel Shooter、Color Blaze Shooter（後者因抄襲下架），以及輸送帶再詮釋的 Car Sort（Rollic）、Jelly Busters（Moon Active）、Yarn Loop（Spyke Games）（AppMagic H1 2026）
- **投放熱度依據**：
  - **營收**：上線 4 個月日收 $500K 以上；2025-12 約日收 $550K（IAP $300K+、廣告占 30–40%）、日下載約 20 萬、DAU 約 100 萬、每人每天約 1 小時 / 10 次（[Deconstructor of Fun 2026-02-13](https://www.deconstructoroffun.com/blog/2026/2/13/pixel-flow-the-publishers-dream)）。AppMagic：2026-04 單月玩家消費峰值 $27M、首年玩家消費約 $200M（[PocketGamer.biz](https://pocketgamer.biz/pixel-flow-wins-game-of-the-year-at-the-pocket-gamer-mobile-games-awards-2026/)）；IAP 累計 $105M（約 2026-06，[mobilegamer.biz](https://mobilegamer.biz/data-digest-pixel-flow-hits-100m-mays-top-games-neverness-to-everness-pokemon-go-more/)）、一年內破 $125M（[AppMagic H1 2026](https://appmagic.rocks/research/casual-report-H12026/?hl=en)）。
  - **下載**：兩大商店合計遠超 3,000 萬，美國最多（PocketGamer.biz）。
  - **品類影響**：AppMagic 指 2026 年初 Pixel Flow 把 Sort 推過 Blast，成為益智類 IAP 第三大子類（[AppMagic](https://appmagic.rocks/blog/new-puzzle-order-sort-block-screw)）；上架名稱或描述含「pixel」的新作 137 款、含「flow」194 款。
  - **獎項**：Pocket Gamer Mobile Games Awards 2026 年度遊戲 + 最佳創新 + 最佳開發商 + Rising Star。
  - **廣告投放（北美）**：AdMapix 抽樣美國 30 天（至 2026-08-19）：45 支素材中 4 支純可玩、41 支影片；可玩承擔 75.1% 曝光；單一支 2025-12-13 首見的可玩素材占前 15 名曝光的 78.1%；Android 占 92.4% 曝光；影片多為 59 / 60 秒長版（[AdMapix](https://www.admapix.com/blog/ad-intelligence/pixel-flow-ad-strategy-2026)）。同報告顯示美國下載與營收排名在 2026 年中已下滑。
  - **台灣**：未取得台灣排名或投放數據（知識缺口）。
- **廣告真實度**：**真實玩法為主**。投放主力是可玩廣告，可玩本身就是核心玩法；DoF 另指出美術刻意用「卡通動物（尤其貓）、類超級英雄」等灰色地帶視覺壓低 CPI（影片內容是否全為實機，未證實）。
- **技巧 vs 選擇 vs 運氣**：盤面**完全確定、無隨機**；失敗來自出射順序錯誤或時機不對。另有「連點快送」（slinging）的手速成分，是少見的「排序 + 操作」雙技巧。

## 一句話玩法

點選帶彈數的同色射手送上環繞畫作的輸送帶，打光同色像素方塊把整張像素畫清空。

## 為什麼廣告有效（Hook）

| 元素 | 說明 |
|---|---|
| 前 3 秒畫面 | 一張可辨識的像素畫（動物、角色），射手沿輸送帶繞行、彩色子彈把像素一格格削掉，畫面「被吃掉」的過程本身就好看。 |
| 失敗誘導（fail bait） | 等待格（5 格）快滿、輸送帶塞車；最後剩一小塊顏色卻沒有對應射手可派。 |
| 「我來一定行」的錯誤示範 | 示範者先派了打不到的顏色（目標被別色擋住），射手白繞一圈、占住等待格。觀眾一眼看出「應該先派外層那個顏色」。 |
| 爽感 / 解壓點 | 連發子彈 + 方塊碎裂的節奏感；整張畫清空的完成感；連點快送時的手速快感。 |

## 遊戲規格

### 核心循環
1. 畫面上方：像素畫（每個像素是一個有顏色的方塊）。
2. 下方：數列射手佇列（玩家只能點每列**最前面**那個，DoF）；每個射手有顏色與頭上的彈數。
3. 點擊 → 射手進入輸送帶繞著畫作移動，沿途對**同色**方塊射擊，每發消 1 格。
4. 彈數打完 → 射手離場；繞完一圈仍有彈 → 進入 **5 格等待區**（Google Play / BlueStacks 官方描述）。
5. 點等待區的射手可再送上輸送帶。
6. 全部方塊清空 = 過關；等待區滿且無法再行動 = 失敗。

### 規則與勝負
- 射手只打自己顏色；彈數 = 能打的次數（官方描述）。
- 輸送帶有**容量上限**，滿了必須等（官方描述；確切數值未證實，畫面常見「x/5」之類計數，未證實）。
- 雙格射手（double blocks）占 2 個格位（DoF）。
- **Slinging**：快速連點可暫時讓輸送帶上單位疊到 10 個、超過上限，節奏錯了盤面會崩（DoF）。
- 射擊目標選擇：推測為射手所在邊、視線上最外層的同色方塊（**未證實**）；被別色擋住則打不到，這是排序謎題的來源。
- 盤面與射手佇列完全確定，無隨機（DoF）。

### 操作
- 單點：點佇列最前面的射手、點等待區射手。
- 高階：連點節奏（slinging）。

### 關卡結構與難度曲線
| 關卡段 | 新元素 | 難度槓桿 |
|---|---|---|
| 1–10（未證實） | 2–3 色、小圖 | 佇列短、彈數剛好 |
| 10–20（未證實） | 多列佇列、顏色被包在內層 | 先後順序依賴變深 |
| 20+ | 雙格射手、更大圖 | 等待區壓力、彈數不足需二次上帶、slinging 時機 |

### 計分 / 星等 / 獎勵
- 原作以過關制為主，過關給金幣（細節未取得，未證實）。

### 失敗與轉換點（廣告續命、IAP、導流到主遊戲的位置）
- 生命：可看 rewarded 廣告換生命（DoF）。
- 插頁：失敗必出、勝利後有時出；約第 20 關後明顯變密，開飛航模式也躲不掉（DoF；Google Play 玩家評論稱第 19 關後每關都有強制廣告）。
- IAP：「Remove Ads」轉換佳（因為廣告夠煩）；道具（power-ups）存在，玩家抱怨關卡設計成不用道具會輸好幾次（Google Play 評論，未證實）。
- DoF 的結論：難度被刻意保護，因為**難度本身驅動 IAP**，不提供繞過難度的廣告捷徑。

## 可玩廣告（Playable Ad）結構

- 美國投放以可玩為主（曝光 75%），且一支可玩長期霸榜（2025-12 → 2026-08 仍在跑）。
- 推測結構（未證實）：0–2 秒一張小像素畫 + 手指提示點最前排射手 → 3–6 次點擊清掉大部分 → 最後剩被包住的一塊、等待區快滿 → 失敗或完成畫面 → CTA。
- 影片長版 59–60 秒為主，影片多附可玩連結（41 支影片中 27 支附可玩）。

## 技巧要素

| 技巧 | 影響 |
|---|---|
| 出射順序（由外而內） | 主技巧；決定會不會卡住等待區 |
| 彈數管理 | 高彈數先上清大片、低彈數留著收尾（同類遊戲攻略建議，未證實為原作官方） |
| 等待區 / 輸送帶容量控管 | 失敗條件本身 |
| Slinging 連點節奏 | 手速技巧；可暫時超載換取時間 |

## 隨機 / 選擇噱頭

- 原作沒有隨機；「看似隨手點、其實要規劃」是本品類最大的廣告賣點。
- 唯一的不透明是「目標怎麼選」——玩家要靠經驗理解射擊規則。

## Skill Game 化改造（必做）

> 用這份規格書做遊戲時（含「復刻」），玩法規格 `gdd/05_game_spec.md` §13 要逐條回應下列每一條：採用就寫本作做法，不採用就寫理由與替代做法。「復刻」只復刻玩法結構與操作，不跳過本節（`RULE-AF-ADAPTATION`，`npm run audit` 檢查）。

1. **同種子**：`rng(seed,"level",i)` 從手工關卡池（建議 ≥ 300 關）抽 5 關；關卡可水平鏡像、顏色置換增加變化（置換不改解）。
2. **確定性 sim**：輸送帶用整數路徑參數 `t ∈ [0, L)`，每 tick 前進固定格數；射擊判定在固定 tick 間隔（例：每 4 tick 一發）；目標選擇規則明確公開（射手所在邊、該列 / 欄最外層同色格），玩家可學。
3. **限時 + 連續計分**（原作是過 / 不過）：每關 45 秒，計分：
   - 每清 1 格 +10
   - 過關 +500 + 剩餘秒數 × 20
   - 射手**零浪費**獎勵：射手離場時彈數剛好用完 +30（鼓勵精準排序）
   - 等待區高水位懲罰：每 tick 等待區 ≥ 4 格，−1（鼓勵不囤積）
   - 未過關：只拿已清格數分，不歸零
4. **保留 slinging 當技巧天花板**，但輸入要走時間戳佇列（見 [13 輸入公平性](../13_input-fairness.md)），以 sim tick 判定，不吃幀率。
5. **移除付費影響**：無續命、無道具；若要道具，每局每人固定同一組（例：1 次「+1 等待格」），不可購買。
6. **對戰形式**：非同步同種子 5 關連戰，總分排行；約 3–4 分鐘。也可做 1v1 即時鬼影（顯示對手清除進度條）。
7. **與原作拉開距離**：不用「豬 + 輸送帶 + 像素畫」三件組合的原樣（Color Blaze Shooter 因抄襲下架是前車之鑑），射手、題材與目標規則都要自訂。

## HTML5 輕量實作規格

| 項目 | 規格 |
|---|---|
| 畫面 | 直版 720×1280；畫作區 640×640（像素畫 16×16～32×32 格，每格 20–40 px）；輸送帶為環繞畫作的圓角矩形；下方 5 格等待區 + 3–4 列射手佇列 |
| 實體與資料結構 | `pixels: Uint8Array(W*H)`（0 空、1–8 色）；`queues[c][]{color, ammo, size(1/2)}`；`belt[]{shooterId, t, ammo}`（容量 cap）；`bench[5]`；`edgeIndex`：每條邊每列 / 欄維護「最外層非空格」索引，射擊 O(1) 取目標；`events[]`（shoot / hit / leave / bench / fail） |
| 關鍵參數 | sim 60 Hz；帶速 L/240 tick 一圈（4 秒，未證實，需調）；射速每 4 tick 一發；輸送帶容量 5（未證實，可調）；等待區 5 格（官方）；slinging 上限 10（DoF）；每關 45 s |
| 渲染 / Draw Call 估計 | 像素畫不逐格建 sprite：用 `Uint8Array` → 1 張小 texture（`BufferImageSource`），nearest 放大：**1 DC**；射手、子彈、碎片、輸送帶共用 atlas：1 DC；分數 BitmapText：1 DC → **約 3 DC**；不用 filter |
| 美術資產清單 | 射手 1 款 × 8 色（tint 處理，只畫 1 張灰階）、雙格射手 1 款、子彈 1、碎片 2、輸送帶 9-slice、等待格 1、像素畫（關卡資料，非圖檔） |
| 包體估計 | 程式 0.8 MB；atlas 0.15 MB；關卡 JSON 300 關 × 32×32 RLE ≈ 0.2 MB（gzip）；音效 0.2 MB；BGM 1.5 MB → **≈ 2.9 MB** |

## 主題與美術風格

- 原作：可愛豬射手、糖果色、像素畫題材廣（動物、物件、角色），DoF 提到刻意用接近知名角色的灰色地帶圖像。
- 改造：像素畫題材全部自繪或程式生成（節慶、動物、食物）；**不得**接近任何知名 IP 角色；射手換成自家角色（如顏料瓶、小砲台、小精靈）。

## 可借用 / 要避開

- **可借用**：確定性盤面 + 「由外而內」的排序心智模型；把畫作清空的完成感；等待區作為唯一失敗條件（規則好懂）；slinging 這種「排序遊戲裡的手速技巧」非常適合 skill game。
- **要避開**：原樣抄三件組（下架風險）；灰色地帶 IP 圖像；把強制插頁當變現核心；難度刻意設計成「不買道具很難過」。
