# 17 遊戲設計原則（手感、節奏、回饋）

> 補本庫缺的「為什麼好玩、怎樣才有手感」這一層。來源：[kociden/sakurai-skill](https://github.com/kociden/sakurai-skill)（非官方，AI 依 YouTube「桜井政博のゲーム作るには」257 集自動字幕整理），本頁以自己的話改寫、只取適合 skill game 的部分，`#數字` 是影片通し番號，可回原影片查證。
> 與其他頁的關係：效果的實作做法與數值在 [05](05_juice-and-feel.md)、[juice.md](../.claude/skills/lite-skillgame-stack/references/juice.md)（`FEEL`）；音效配方在 [14](14_audio.md)；難度曲線與驗收門檻在 [16](16_difficulty-curve.md)；公平性在 [01](01_skill-integrity.md)。本頁只講原則與檢查順序，**不定門檻**：文中出現的數字是來源的經驗值（未證實），不得寫進 `rules.json` 或拿來當驗收條件。

## 0. 來源與使用限制
<!-- card: skip; reason=來源說明，內容已併入頁首 -->

- 對方 repo 沒有授權檔（預設保留所有權利），內容又是二次整理的影片，**不得複製原文進 repo**；本頁是改寫摘要。
- 來源是自動字幕＋AI 摘要，可能有聽寫錯誤；原則偏大型動作遊戲（3D 鏡頭、崖邊、格鬥）的部分沒有收。
- 用法：寫規格（N2）時用 §1–§4 當設計檢查；調手感（N7）時用 §5–§8；有人說「手感弱」「拖沓」時照 §9 的順序查。

## 1. 不適用於 skill game 的原則（排除清單）
<!-- card: KB-design-principles.excluded -->

來源有些建議是為了讓「家用、單人通關」的遊戲更親切，放到同種子、比分數的技巧賽會破壞公平或可證明性。下表的做法**不採用**，引用來源時要避開：

| 來源建議 | 為什麼不能用 | skill game 的替代 |
|---|---|---|
| 落後的玩家給補助、道具（#200 瑪利歐賽車型） | 同一局對手拿到不同條件，比分不再只反映技巧 | 所有人同種子、同難度；回饋與鼓勵只做在表現層 |
| 輸太多就提議降難度、可在局中改難度、跳過難關（#211） | 難度變動會讓分數不可比；違反 `RULE-SKILL-DOMINANCE` 與規格的公平條款 | 降難度只能出現在**練習模式**，且不計分；正式局靠曲線設計（[16](16_difficulty-curve.md)）讓人不卡死 |
| 遊戲內可做到的投機、刷分漏洞不必全修（#048） | 漏洞＝可被腳本放大的理論滿分偏差，直接影響排行與獎金 | 任何能拿分的漏洞都要修或寫進計分上限；見 [13](13_input-fairness.md) 防巨集 |
| 隨機性帶來新鮮感、讓弱者有翻盤機會（#187 的派對向用法） | 運氣決定勝負違反 `RULE-SKILL-NOT-LUCK` | 只用「同種子的隨機」：每個人遇到同樣的變化，比的是應對（#187 也說選項可以隨機、操作要靠技巧） |
| 依玩家強度調整敵人強度 | 同上，分數不可比 | 固定腳本曲線 |

可以照用的是 #168 的觀點：只顯示名次會讓第一名以外的人沒成就感，改用「在全體中的百分位或段位」呈現（[09](09_knowledge-gaps.md) G14 的新手分數呈現）。

## 2. 核心：風險與報酬
<!-- card: KB-design-principles.risk-reward -->

- **好玩＝玩家冒險換取報酬的結構**（#006）。寫規格時要能一句話說出「冒什麼險、換什麼」：越靠近越危險但收穫越大、越晚按越準但越可能失手。
- **風險和報酬要放得近、大小相稱**（#006、#236）：冒大險的操作要給明顯更多分；用「玩家這一下做得有多好」去檢查每項計分與懲罰是否對得上。這正是 skill game 的技巧梯度來源，可直接對應 [01](01_skill-integrity.md) 的技巧軸與 [16](16_difficulty-curve.md) 的容錯參數。
- **先擠壓再釋放**（#009）：給壓力（障害、倒數、密集來襲），再讓玩家用技巧解除並立刻得到獎勵。一局的節奏就是這個循環的重複。
- **舒服的感覺要有反面才成立**（#065 的整理）：快感來自「可能失敗」。把失敗可能性全拿掉，爽度也一起消失。
- **技巧性越高，入門門檻越高**（#146）：同一風險，老手覺得小、新手覺得大。立項時先決定目標玩家，再決定風險大小，不要兩頭都要。
- **平衡不等於平均**（#216、#245）：一直「削強補弱」會讓所有選項變得一樣。有多個角色或技能時，保留長處、同時放大短處；要調弱時改別的軸（硬直、判定、發動時間），不要先砍威力。

## 3. 難度、重試與節奏（技巧賽版）
<!-- card: KB-design-principles.retry-pacing; topic=difficulty,design -->

- **重開要快**（#116）：從失敗到能再操作的時間，比懲罰輕重更決定玩家會不會放棄。失敗演出要短而明確，馬上把操作還給玩家；技巧賽的「再來一局」按鈕要在結算畫面第一眼就按得到。
- **難度不要是一直線的坡**（#105）：難關與喘息段交替，難關要「逼玩家想辦法」而不只是數值更大。這與 [16](16_difficulty-curve.md) 的上升鋸齒、調息、頭目結構一致，驗收照 `RULE-CURVE-*`。
- **開發者會高估玩家**（#254）：做的人太熟，體感難度要比自己覺得的再低一點；自己測時加限制（單手、只看一半畫面）。正式驗收仍以人性化 bot 與真人試玩為準（[16](16_difficulty-curve.md)、N9）。
- **重複遊玩要有「想看下一段」的理由**（#127）：同一關反覆失敗的人一直看同樣的畫面。技巧賽一局很短，至少讓每局的後段有新東西（新的威脅組合、更高倍率）可看。
- **最先決定獎勵**（#075、#023）：骨架一成形就決定玩家拿到什麼；把下一個目標放在眼前（「再 120 分升段」）。skill game 的獎勵只能是外觀、段位、紀錄，不能是數值（見 README 三條原則）。

## 4. 回饋、誇獎與計分呈現
<!-- card: KB-design-principles.praise-score; topic=design,scoring,ux -->

- **做得好要誇**（#095）：光給分不夠，要有演出把玩家的成就放大（完美判定的歡呼、連擊里程碑的印章）。演出不得改變 sim 時序、要可跳過（[05](05_juice-and-feel.md)）。
- **分數的呈現方式決定它有沒有意義**（#198）：把分數換成玩家聽得懂的尺度（百分位、段位、「擊敗 87% 玩家」），結算時快速滾動數字本身也是爽點。
- **每個輸入都要有反應**（#104）：按了沒反應是最糟的體驗；無效時機的點擊也要給「無效」的回饋（輕音、灰色閃一下），讓玩家知道輸入有被收到。這也幫助 [13](13_input-fairness.md) 的延遲校正被玩家信任。

## 5. 導入與時間
<!-- card: KB-design-principles.onboarding-time; topic=ux,design -->

- **一開始就讓玩家玩到精華**（#233、#240）：不要先放長說明或故事；第一局就讓核心操作與一次高潮出現。補 [09](09_knowledge-gaps.md) G14 的 FTUE 方向。
- **教學融入正式玩法**（#085）：不做空白練習場、不放大段文字；用實際局面逼玩家用到該操作。
- **慢是唯一沒人喜歡的東西**（#073、#244）：盤點「玩家真正在操作的時間」佔比；淡入淡出、轉場、等待能縮就縮，寧可稍嫌太快。但完全沒過場會讓人搞不清楚畫面變了，留一點。
- **非遊玩畫面一律可跳過**（#178）：Logo、說明、結算演出都要能跳。
- **玩家的時間是成本**（#248）：局長只保留好玩的部分與支撐它的部分。
- **看不懂文字也能開始**（#238）：從首頁連按確認就能進第一局；重要選項做大（#145）。

## 6. 手感：頓幀、受擊與動作
<!-- card: KB-design-principles.hitstop-motion; topic=juice; kind=method; genre=survivor,arena,shmup,lane-shooter,tower-defense,runner -->

有「打中」概念的品類適用；做法與 `FEEL` 鍵見 [05 §1](05_juice-and-feel.md)，頓幀只停 render、sim 照跑。

| 原則 | 來源 | 落到本庫 |
|---|---|---|
| 頓幀必備；擊破頭目、自己失誤也停一下＋閃一下 | #003 | 這些 sim 事件也觸發頓幀 |
| 停時加微震，**受擊方大、攻擊方小**，只動顯示不動判定；地面橫震、空中可縱震，由大往小收斂 | #047 | 震 sprite 偏移，不碰 sim 座標 |
| 停多久＝攻擊力 × 招式係數；鏡頭越遠振幅越大 | #047 | `FEEL` 用基礎值 × 係數表 |
| 按下第一幀就大幅變姿勢，回應優先於補間流暢 | #049 | 出手不用對稱緩動 |
| 蓄力長、揮出一幀到位、中間格幾乎不要；自動補間會變溫吞 | #148 | `power4.out` / `expo.out` |
| 收招停留最久、決定印象；強招要有明顯硬直才有取捨 | #077 | 硬直寫進規格 |
| 受傷第一幀要極端、不對稱，頓幀中停在這格；受擊方幾幀內過渡到受傷姿勢 | #140、#047 | Spine 短 mix／序列幀放極端格 |
| 沒味道先加擠壓伸展（壓扁時變寬）；角色越小越要誇張 | #120、#028 | 補 `scale.x/y` |
| 判定比外觀略大，「明明打到」是壓力來源 | #223 | 判定寬度寫進規格、所有人一致 |

## 7. 特效：擊中標記、爆炸、震動、閃光
<!-- card: KB-design-principles.effects; topic=juice; kind=method -->

| 原則 | 來源 |
|---|---|
| 不要只靠加算發光；以清楚的形狀為主，並**混入暗色**，亮背景上也看得到 | #016、#130 |
| 擊中標記：強度與效果相稱、從判定重疊處出、多種元素（衝擊環、火花）、不擋住角色、**早點消失**（連擊更短）、頓幀期間仍在動 | #130 |
| 爆炸分段：閃光 → 火焰 → 黑煙 → 收束；太短會沒手感 | #056 |
| 震動的大中小要換「震法」，不只換幅度（小震只縱向、中震加橫向）；先強後衰減、帶一點隨機 | #103 |
| 閃光不要整片純白加算（對比會下降）；**明暗交替**；畫面越近越弱以免刺眼；角色閃色可表示狀態（無敵白、無防備黃） | #221 |
| 特效不能蓋住角色：2D 調圖層順序、或在中央留空、加描邊 | #035 |
| 粒子壽命短、數量少、錯開不重疊；與其很多小粒，不如少數大張帶圖案 | #242 |
| 特效尺寸要符合世界比例（劍上的火不要小得像燭火） | #199 |

無障礙：閃光與震動的上限照 [05 §3](05_juice-and-feel.md) 與 [15 §4.1](15_reference-games.md)，`prefers-reduced-motion` 只拿掉動態、不拿掉資訊。

## 8. 音效：依影響度排優先序
<!-- card: KB-design-principles.audio-priority; topic=audio; kind=method -->

- **音量與醒目度依「對勝負的影響」排序**（#032），不是看哪個音比較好聽。來源的格鬥遊戲順序是：擊殺 ＞ 命中、完美防禦 ＞ 必殺、語音 ＞ 爆炸 ＞ 迴避 ＞ 揮空 ＞ 跳躍落地 ＞ 腳步 ＞ 環境音。換成 skill game：**判定結果（完美、命中、失誤）最清楚**，連擊里程碑次之，裝飾音最後——與 [14 §3](14_audio.md) 的混音原則一致。
- **命中音起音要強、殘響適中**（#165）：一開始就到峰值，殘響短，連擊時才不會糊成一片；重擊最好在頓幀期間就播完主體。這對應 [14 §2](14_audio.md) 配方的短包絡。
- **連發的音要有變化**（#032）：同一個音重複會很機械——[14 §1](14_audio.md) 的 ±4% 音高已在做。
- **BGM 速度配合操作速度**（#025）：快節奏操作配快歌（來源說格鬥對戰曲多在 130–170 BPM，未證實），難度上升時可同步提速。
- **在爛喇叭上聽**（#054）：手機外放會吃掉低音，`boom` 這類低頻音要確認手機上仍聽得到。
- **判斷標準是「合不合遊戲目的」**（#165），不是「是不是好音」。

## 9. 審查順序：「手感弱」「拖沓」時先查什麼
<!-- card: KB-design-principles.review-order; topic=juice,audio,ux; kind=method -->

每項改完再試玩，一次只改一項，並附改法（只批評沒用）。

- **手感弱**：頓幀與受擊震動（§6）→ 擊中標記醒目度與停留時間（§7）→ 命中音起音與殘響（§8）→ 重擊的震動與閃光（§7）→ 出手第一幀與受傷格（§6）
- **拖沓**：實際操作時間佔比（§5）→ 轉場與結算能否縮短或跳過（§5）→ 失敗到再操作的時間（§3）→ 輸入第一幀反應、補間是否溫吞（§6）
