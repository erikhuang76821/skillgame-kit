# 11 地表設定集 — 共用美術規則＋生成提詞＋整合提詞

> 用途：每款新遊戲的地表（地面材質、交界、高低差）都從這套提詞起手。換遊戲時**只替換【】內的內容**，不帶入舊專案名稱、尺寸或技術架構。
> 原則：像素尺寸、過渡寬度、飽和度等**數值一律放在各遊戲的參數表（§4）**，不寫死在提詞裡。
> 相關：[06 美術管線](06_art-pipeline.md)、[07 題材](07_themes-and-liveops.md)、[04 技術框架](04_tech-stack.md)、[10 資產庫](10_asset-library.md)

## 0. 怎麼用
<!-- card: KB-terrain-style-kit.how-to; kind=method -->

| 步驟 | 用哪段 | 產出 |
|---|---|---|
| 1 | 填 §4 參數表（存成 `<NewGame>/gdd/12_terrain.md` 或 `art/terrain.json`） | 本作的數值 |
| 2 | ① 共用美術規則：所有美術提詞的前置段落 | 風格一致 |
| 3 | ② 地表材質生成（每種材質一次）→ §3.2 後處理 | 可平鋪的材質 tile |
| 4 | ④ 立體面生成（有高低差 / 3D 才用） | 崖面、高度圖 |
| 5 | ③ 地形程式整合：交給寫程式的 AI | 地形資料、交界、快取 |
| 6 | ⑤ 驗收清單 | 通過才進遊戲 |

## 1. 原版提詞（v1，使用者定稿，原文保留）
<!-- card: KB-terrain-style-kit.prompt-v1 -->

### ① 共用美術規則

```
為一款【遊戲類型】建立一致的視覺風格。
美術風格：【例如：清晰、細緻的像素風】
場景主題：【例如：森林、遺跡、荒原】
視角：【正俯視／俯視 3/4，擇一】
主色盤：【指定主要色系】
視覺優先順序：
角色與敵人最容易辨識，其次是互動物件與危險提示，地表作為背景。
地表使用較低飽和度、較低對比與適量灰調，細節保持細小、疏密自然。角色、敵人與重要效果保留較清楚的輪廓及色彩差異。
所有素材維持一致的視角、光源、像素密度與比例。避免裝飾細節干擾操作、目標辨識或危險判讀。
```

### ② 地表材質生成

```
沿用共用美術規則，生成【材質名稱】的遊戲地表紋理。
整張畫面填滿同一種材質，可上下左右無縫平鋪。保持均勻光照，以細小、低對比的紋理呈現自然變化。
不要畫出獨立的土地輪廓、道路形狀、矩形區塊或場景構圖。不要加入角色、建築、大型物件、投影、文字、格線或邊框。
輸出不透明 PNG。每種材質獨立輸出，維持相同的像素密度與色彩風格。
```

### ③ 地形程式整合

```
將地表材質整合進現有遊戲，沿用專案的引擎、座標與資產規格。
將地形資料、外觀生成、碰撞與物件繪製分開管理。材質貼圖只提供表面細節，不直接決定地形輪廓或碰撞。
依相鄰地形產生連續交界：
* 相同材質相接時合併，不留下內部接縫。
* 不同材質使用自然起伏、柔化轉角與少量碎粒過渡。
* 避免矩形貼片、筆直切線、規律鋸齒及過度模糊。
* 使用固定種子，讓邊界與細節穩定、不隨畫面更新跳動。
地表調色只作用於背景層，不影響角色、敵人、危險提示及技能特效。依場景規模快取整張地圖或可見區塊，避免每幀重建。
若為既有遊戲，保留原本的通行路線、碰撞與玩法資料。
完成後檢查：材質接縫、邊界形狀、角色辨識度、通行一致性，以及正常遊玩鏡頭下的整體效果。
```

## 2. 差異分析：建議調整與補充
<!-- card: KB-terrain-style-kit.diff-analysis; kind=lesson -->

對照 repo 既有知識（Skill Game 公平原則、像素管線踩過的坑、DC / 包體規範），v1 方向正確；以下是**加上去才不會在不同遊戲間失靈**的差異。標 ★ 為 Skill Game 特有、最重要。

### 2.1 ① 共用美術規則

| # | 類型 | 差異 | 理由 |
|---|---|---|---|
| A1 | 補參數 | 加【光源方向】（例：左上）與【陰影政策】（地表無投影 / 角色陰影由程式畫） | v1 說「一致光源」但沒指定；立體面（崖、牆）一定要有明確光向，否則每張生成的明暗不一 |
| A2 | 補參數 | 加【像素密度】欄位（美術 px ↔ 世界單位）、【鏡頭距離 / 目標裝置】 | 「一致像素密度」需要可比對的基準；手機直版小螢幕的可讀性與電腦不同 |
| A3 ★ | 補規則 | 加【保留色】：危險提示、可互動物、技能特效專用的色相（例：紅橘＝危險、亮青＝拾取），**地表不得使用** | 公平與可判讀：地表與危險色撞色 = 玩家看不到警示，等同視野不公平（精髓 E3） |
| A4 | 補規則 | 地表亮度落在【亮度帶】內、與角色主色保持【最小明度差】；灰階截圖仍可分辨角色與危險 | 「低飽和、低對比」是質性描述，跨遊戲需可驗證的數字（數值放 §4） |
| A5 | 補規則 | 加色盲安全：危險 / 安全不只靠紅綠區分，搭配形狀或明度 | 北美上架與無障礙 |
| A6 | 補規則 | 加市場禁忌與負面詞（見 [07](07_themes-and-liveops.md)：no slot machine / chips / dice / jackpot 等） | 避免賭場觀感，與 skill 定位一致 |

### 2.2 ② 地表材質生成

| # | 類型 | 差異 | 理由 |
|---|---|---|---|
| B1 ★ | 補流程 | 「無縫平鋪」**不能只靠提詞**：生成後必做半位移（offset ½）檢查接縫，不合格就修補或重生（§3.2） | 圖像模型常產生近似但不真正無縫的圖 |
| B2 | 補規則 | 指定**正投影、無透視**（即使遊戲是 3/4 視角，地面材質仍是正上方拍攝的平面） | 3/4 視角時模型容易畫出遠小近大的地面，平鋪後會「波浪」 |
| B3 | 補參數 | 加【變體數】：每材質 2–4 個同色調變體 + 程式低頻色偏 | 大面積單一 tile 會看出重複格紋 |
| B4 | 補規則（像素風） | 像素風改用「真低解析度方塊像素」寫法（每個美術像素 = 等大方塊，無抗鋸齒、無漸層），後處理縮到目標 tile 並硬映射共用色盤 | SwarmDuel 經驗：一般寫法縮圖後細節糊掉（見 [06 §3](06_art-pipeline.md)） |
| B5 | 補規則 | 指定輸出尺寸與 tile 尺寸關係（例：生成大圖 → 縮成【tile 尺寸】），2 的冪次較安全 | GPU 重複取樣、mipmap、atlas 打包 |
| B6 | 補流程 | 提詞不得要求模型存檔；用 codex-image 流程從 session 目錄複製 | Windows 沙箱靜默失敗（既有坑） |
| B7 | 補規則 | 平坦材質「均勻光照」維持；但**崖面 / 牆面另用 ④**，遵守 A1 光向 | 立體面需要明暗才讀得出高低 |

### 2.3 ③ 地形程式整合

| # | 類型 | 差異 | 理由 |
|---|---|---|---|
| C1 ★ | 補規則 | 區分**影響玩法的地形**（通行、減速、高度、遮擋視線）與**純外觀**：前者的資料由 sim 層以種子決定性產生（整數格、`rng(seed,'terrain',i)`），render 只讀；後者（交界雜訊、碎粒、裝飾）可在 render 以固定種子產生 | 同種子對戰時所有玩家地形必須相同，且伺服器重播要能算到相同碰撞 |
| C2 | 補技術 | 列出交界做法供選：① 雙網格 autotile（marching squares，16 種組合）② 遮罩 + 雜訊混合（splat map，shader 或預烘）③ 預烘到 RenderTexture 區塊 | 不同畫風 / 規模選不同法；寫明才不會每款重新摸索 |
| C3 | 補規則（像素風） | 像素風的交界用**抖色 / 碎粒 / 階梯邊**，對齊像素格，不用半透明羽化 | v1 的「柔化」在像素風會變成糊邊 |
| C4 | 補規範 | DC 與記憶體：地表合計目標 ≤ 1–2 DC；整張預烘的 VRAM = 寬×高×4 bytes，超過【快取上限】改區塊快取（例：512² 區塊、只保留可見 + 一圈） | 與 [04](04_tech-stack.md) 的 DC ≤ 5 預算一致 |
| C5 | 補規範 | 若本作覆寫禁用 filter（如 SwarmDuel），交界不得用 filter；改預烘或 Mesh shader | 專案覆寫優先 |
| C6 | 補規則 | 圖層順序沿用契約：ground → 地面效果 / 裝飾 → Y 排序角色；裝飾放置用固定種子、避開通行路線與危險區 | 裝飾不得遮擋判定 |
| C7 | 補流程 | 動態效果開關：LOW / reduced-motion 下地表不做任何動態（流水、搖草） | 與 [05 §3](05_juice-and-feel.md) 一致 |

### 2.4 驗收補充（⑤）

v1 的檢查項保留，另加：2×2 平鋪預覽、灰階截圖、色盲模擬、實機尺寸截圖、DC 與 VRAM 量測、同種子兩次產生的地形雜湊相同。

## 3. 修訂版提詞（v2：v1 ＋ 差異，仍只替換【】）
<!-- card: KB-terrain-style-kit.prompt-v2 -->

### ① 共用美術規則（v2）

```
為一款【遊戲類型】建立一致的視覺風格。
美術風格：【例如：清晰、細緻的像素風】
場景主題：【例如：森林、遺跡、荒原】
視角：【正俯視／俯視 3/4／等角／3D 固定鏡頭，擇一】
光源：【例如：左上方】；地表不畫投影，角色陰影由程式繪製。
主色盤：【指定主要色系】
保留色：【例如：紅橘＝危險提示、亮青＝可拾取】——地表與裝飾不得使用這些色相。
像素密度：【美術像素與遊戲單位的比例】；目標裝置：【例如：手機直版】。
視覺優先順序：
角色與敵人最容易辨識，其次是互動物件與危險提示，地表作為背景。
地表使用較低飽和度、較低對比與適量灰調，細節保持細小、疏密自然。角色、敵人與重要效果保留較清楚的輪廓及色彩差異；轉成灰階後仍能分辨角色、地表與危險提示，危險與安全不只靠紅綠區分。
所有素材維持一致的視角、光源、像素密度與比例。避免裝飾細節干擾操作、目標辨識或危險判讀。
不要使用：【市場禁忌與負面詞，例如：老虎機、籌碼、骰子、彩金字樣】。
```

### ② 地表材質生成（v2）

```
沿用共用美術規則，生成【材質名稱】的遊戲地表紋理（第【n】個變體，與其他變體同色調、同密度）。
以正上方正投影呈現，沒有透視、沒有遠近大小差異。
整張畫面填滿同一種材質，可上下左右無縫平鋪。保持均勻光照，以細小、低對比的紋理呈現自然變化。
【像素風才加：以真正的低解析度像素畫繪製，每個美術像素是等大、邊緣銳利的方塊，無抗鋸齒、無漸層、無模糊。】
不要畫出獨立的土地輪廓、道路形狀、矩形區塊或場景構圖。不要加入角色、建築、大型物件、投影、文字、格線或邊框。
輸出不透明 PNG。每種材質獨立輸出，維持相同的像素密度與色彩風格。
```

### ④ 立體面生成（新增：有高低差或 3D 時）

```
沿用共用美術規則與既有地表材質，生成【崖面／牆面／台階側面】的紋理，用於【材質名稱】高台的垂直面。
光源固定在【光源方向】：朝光面較亮、背光面較暗；頂緣保留一道與上層地表同色系的亮邊，底部漸暗與下層地表銜接。
紋理可左右無縫平鋪；上下方向保留頂緣與底緣，不需平鋪。
保持低飽和、低對比，不得比角色更搶眼。不要加入角色、植物群、大型物件、文字、格線或邊框。輸出不透明 PNG。
```

```
（3D 用，選用）生成【材質名稱】的灰階高度圖：白色為高、黑色為低，起伏細小且可上下左右無縫平鋪，無光影、無顏色、無文字。
```

法線貼圖由程式從高度圖推導，不用生成模型直接畫（光向與強度才可控）。

### ③ 地形程式整合（v2）

```
將地表材質整合進現有遊戲，沿用專案的引擎、座標與資產規格，並遵守專案的效能與圖層規範。
將地形資料、外觀生成、碰撞與物件繪製分開管理。材質貼圖只提供表面細節，不直接決定地形輪廓或碰撞。
會影響玩法的地形（可否通行、速度、高度、視線）由模擬層依種子產生並以整數格保存，畫面層只讀取；純裝飾的細節由畫面層以固定種子產生。
依相鄰地形產生連續交界（做法：【雙網格自動拼接／遮罩混合／預先烘焙】）：
* 相同材質相接時合併，不留下內部接縫。
* 不同材質使用自然起伏、柔化轉角與少量碎粒過渡；【像素風：以抖色、碎粒或階梯邊對齊像素格，不用半透明羽化】。
* 避免矩形貼片、筆直切線、規律鋸齒及過度模糊。
* 使用固定種子，讓邊界與細節穩定、不隨畫面更新跳動。
【有高低差時：依高度分層繪製，崖面使用立體面紋理；角色被高處遮擋時顯示輪廓；坡道與台階是唯一的跨層通道。】
地表調色只作用於背景層，不影響角色、敵人、危險提示及技能特效。依場景規模快取整張地圖或可見區塊，避免每幀重建；地表合計繪製次數與記憶體不超過【預算】。
降低特效模式下，地表不播放任何動態效果。
若為既有遊戲，保留原本的通行路線、碰撞與玩法資料。
完成後檢查：材質接縫、邊界形狀、角色辨識度、危險提示可見度、通行一致性、同種子重建結果一致，以及正常遊玩鏡頭下的整體效果。
```

### 3.2 生成後處理（程式，不靠提詞）

1. 縮到【tile 尺寸】（像素風：Lanczos 縮小 → 硬映射本作共用色盤 → 不抖色；非像素風：直接縮）。
2. **半位移檢查**：把圖平移 ½ 寬高，接縫若可見 → 在中央十字帶做鏡像混合修補，或重生。
3. 2×2 平鋪預覽人工驗收。
4. 低頻色偏與變體由程式在執行期以固定種子分配，不另生大圖。

## 4. 各遊戲參數表（彈性設計的核心：數值只放這裡）
<!-- card: KB-terrain-style-kit.params -->

| 參數 | 說明 | 範例（僅示意，各遊戲自訂） |
|---|---|---|
| `view` | 正俯視 / 3/4 / 等角 / 3D 固定鏡頭 | 3/4 |
| `light` | 光源方向 | 左上 |
| `artPxPerUnit` | 美術像素 ↔ 世界單位 | 1 : 2 |
| `tileSize` | 材質 tile（美術 px） | 32 / 64 / 128 |
| `materials[]` | id、名稱、變體數、可否通行、速度係數 | grass / dirt / water |
| `palette` | 共用色盤（像素風必填） | 24 色 |
| `reservedHues` | 保留色 | 危險紅橘、拾取亮青 |
| `groundLuma` | 地表亮度帶 | 0.25–0.45 |
| `minLumaGap` | 角色主色與地表最小明度差 | 0.25 |
| `groundSatMax` | 地表飽和度上限 | 0.35 |
| `transition` | 交界做法、寬度、樣式（柔邊 / 抖色 / 碎粒） | 雙網格、6 px、碎粒 |
| `decor` | 裝飾種類、密度、避開區域 | 每 1000 單位² 3 個 |
| `cache` | 整張 / 區塊大小 / 保留圈數 / VRAM 上限 | 區塊 512²、上限 32 MB |
| `heights` | 高度層數、每層像素高、坡道規則（無高低差填 0） | 3 層、16 px |
| `gameplayTerrain` | 地形是否影響玩法（是 → 由 sim 產生） | 是 |
| `dcBudget` | 地表 DC 上限 | 1 |

## 5. 立體地圖面：依視角的變體
<!-- card: KB-terrain-style-kit.3d-variants -->

| 視角 | 地形資料 | 繪製 | 材質需求 | 注意 |
|---|---|---|---|---|
| **平面（正俯視 / 3/4）** | 2D 材質格 | TilingSprite / 預烘區塊；交界雙網格或遮罩 | ② 平面材質 | 現行 SwarmDuel：單材質程式草地 + 固定種子裝飾 |
| **2.5D 高低差**（平面 + 台地 / 崖） | 材質格 + 整數高度格；坡道 / 台階為跨層連通 | 依高度分層，同層內依腳底 Y 排序；崖面為獨立帶狀 sprite | ② + ④ 崖面（明暗依光向） | 角色在崖後要顯示輪廓；碰撞依高度差（sim 整數判定）；高處視野不得多於低處（E3） |
| **等角（2:1 菱形）** | 同上，座標轉換 iso | 菱形 tile；排序鍵 = (x+y)、高度 | **先生成正投影材質，再以程式仿射轉成等角**（不要直接請模型畫等角 tile，無縫難保證） | 角色 sprite 方向要改等角 8 向，影響 sprite 契約；像素線條用 2:1 階梯 |
| **真 3D（ogl / three，固定鏡頭）** | 高度場（整數格，玩法用）＋ 外觀網格 | 一個地形 mesh；splat 遮罩一次混合 ≤ 4 材質（1 DC）；陡坡用 triplanar 避免拉伸 | ② 材質（albedo）＋ 選用高度圖 → 程式推導法線；≥ 512² 用 KTX2 | **玩法高度只用 sim 的整數格**，不用 mesh 射線（浮點、跨引擎不一致）；鏡頭固定，所有玩家視野相同；地形 DC 計入 3D ≤ 9 |

選擇建議：Skill Game 多數用平面或 2.5D 就夠；等角與 3D 的成本主要在角色素材（方向數、模型），不是地表。決定前先估角色資產量（見 [06](06_art-pipeline.md)）。

## 6. ⑤ 驗收清單
<!-- card: KB-terrain-style-kit.acceptance; kind=method -->

- [ ] 每個材質 2×2 平鋪無可見接縫；半位移檢查通過
- [ ] 大面積無明顯重複格紋（變體 + 色偏）
- [ ] 交界無矩形貼片、直線切邊、規律鋸齒、過度模糊；像素風邊緣對齊像素格
- [ ] 灰階截圖：角色、危險提示、地表三者可分辨；色盲模擬下危險提示可辨
- [ ] 地表未使用保留色；亮度、飽和度在參數表範圍內
- [ ] 實機尺寸（目標裝置）截圖檢查可讀性
- [ ] 同種子重建兩次，地形資料雜湊相同；影響玩法的地形來自 sim
- [ ] 通行一致：畫面上看得到的邊界 = 碰撞邊界
- [ ] 地表 DC ≤ `dcBudget`；VRAM ≤ `cache` 上限；不每幀重建
- [ ] LOW / reduced-motion 下地表無動態
- [ ] 有高低差：崖後角色可見輪廓、坡道 / 台階為唯一跨層通道、高處不多看世界

## 7. 參考實作（範本內建，2026-10-19）
<!-- card: KB-terrain-style-kit.reference-impl; topic=art,tech -->

範本 `.claude/skills/lite-skillgame-stack/templates/` 已附一套可直接用的平面 / 2.5D 地形，示範遊戲的背景就是它（0 bytes 圖片、基礎 DC 1、手機與桌面 60 FPS）。

| 檔案 | 層 | 作用 |
|---|---|---|
| `src/sim/core/grid.js` | sim（確定性） | `makeTerrain(seed, …)` 產生材質格與高度格（整數 fbm + 門檻 + 多數決平滑）；`smoothCellAt()` 圓角形狀查詢——**sim 碰撞與畫面共用同一個函式**；`cornerMask()` 給想用 16 格 autotile 的專案；`terrainHash()` 驗證 |
| `src/render/terrainBake.js` | render（純函式，可測） | 形狀 + 長波 / 短波擾動（總量 ≤ `edge`）、邊界碎粒、材質以世界座標取樣（同材質無接縫）、低頻明度漂移（藏平鋪重複）、**3/4 高度投影**（高台頂面上移 `cliffPx`、南側露出崖面、高台正後方的低地被擋住）、側緣暗線、每層加亮；`elevatedComponents()` 把高台分成連通元件，並輸出每個像素屬於哪個元件 |
| `src/render/terrain.js` | render（Pixi） | 依可見範圍預烘區塊成貼圖、LRU 快取、不每幀重建；每座高台另切「遮擋片」放進角色的 y 排序容器（`zIndex` = 高台北緣 − 1）；`isOccluded(x, y, level, w, h)` 判斷角色是否被高台擋住；`screenY()` 做世界 → 畫面高度換算 |
| `src/render/xray.js` | render（Pixi） | 開機時由角色貼圖自動產生 1 px 輪廓貼圖（0 bytes），畫在遮擋片之上，只在被擋住時顯示 |
| `src/render/terrainConfig.js` | 設定 | §4 參數表的程式版：`tile`、`scale`、`chunk`、`cacheChunks`、`edge`、`edgeScale`、`edgeLongScale`、`grain`、材質色盤與門檻、`levels`、崖面樣式 |
| `tools/tile_check.py` | 美術驗收 | 生成材質 tile 的接縫比、亮度帶、飽和度、保留色、alpha；`--preview` 輸出 2×2 與半位移圖 |
| `test/terrain.test.mjs` | 測試 | 種子決定（golden hash）、無孤立格、tile 可平鋪、同材質無接縫、**畫面 = 碰撞形狀（誤差 ≤ edge）**、邊界不筆直、圓角、投影（頂面上移、南側崖面）、**遮擋**（高台正後方的低地被擋、排序鍵讓後方角色在下、高台上與前方角色在上）、烘焙決定性 |

**做法選擇**：不用 16 格 autotile 貼圖，改用「圓角形狀 + 種子擾動」逐像素烘焙。理由：任意材質數都不需要多做過渡圖；自動滿足 ③ 的合併、柔角、碎粒、不筆直、固定種子；像素風邊緣天然對齊像素格。代價是烘焙時間（Node 實測 768×512 美術像素約 0.3 s），所以一定要區塊快取、只在載入或鏡頭進入新區塊時烘。

**接 AI 生成材質（已實作，2026-10-19）**：在 `terrainConfig.js` 的材質加 `src`，`loadTiles(cfg)` 讀成 `{ w, h, data }` 交給 `TerrainView`；圖片載入失敗時退回程式產生的 `noiseTile()`。範本的「dust」就是用 v2 提詞（②，填入「乾燥塵土地、夜晚荒原、暗灰褐與冷灰藍、保留亮綠 / 亮藍 / 紅橘」）實際生成：

| 階段 | 結果 |
|---|---|
| 生成（Codex / gpt image） | 1254×1254，像素方塊、低對比、無物件 / 文字——但 **`tile_check` 接縫比 4.26，不及格**（模型宣稱可平鋪，實際不行） |
| `tools/tile_prep.py --size 128 --colors 8 --luma 0.12,0.24 --sat-max 0.30` | 置中裁切 → 方塊縮到 128 → 半位移抖色混合讓邊界可平鋪 → 亮度 / 飽和度拉進範圍 → 8 色量化 |
| `tile_check` | **PASS**：接縫 0.81、亮度 0.238、飽和度 0.12、無保留色、不透明；20.6 KB |

提詞原文與來源記在 `src/assets/terrain/dust.prompt.txt`。教訓：生成的「無縫」一律不可信，後處理是必要步驟；載入要用 `onload` 而不是 `img.decode()`（背景分頁中 `decode()` 可能一直不回來，整個開機卡住）。

**遮擋怎麼運作（2.5D）**：

| 角色位置 | 世界腳底 y 與排序鍵 | 畫法 |
|---|---|---|
| 高台正後方的低地 | y < 北緣 − 1 → 排在遮擋片之前 | 被高台頂面 / 崖面蓋住；`isOccluded()` 為真 → 顯示輪廓 |
| 高台上 | y ≥ 北緣（sim 的 `smoothCellAt` 保證高台地面不會在北緣以北） | 畫在遮擋片之上；畫面 y 上移 `level × cliffPx` |
| 高台前方 / 側邊 | y > 北緣 | 畫在遮擋片之上 |

接入正式遊戲：角色 sprite 放進傳給 `TerrainView` 的 y 排序容器、`zIndex` = 世界腳底 y、位置用 `screenY(y, level)`；每幀對需要的角色（通常是玩家與危險敵人）呼叫 `isOccluded()` 並 `xray.sync()`。輪廓色要避開地表色盤與保留色。

**已知限制**：排序以「整座高台」為單位——形狀很不規則的高台（例如 U 形）缺口裡的角色可能被錯排，必要時把它拆成兩個元件或降低高度；遮擋片數 = 區塊數 × 每區塊高台數，示範 7 片仍是 1 DC，過多時會超過一批 16 張貼圖。遮擋只影響畫面；被擋住的敵人仍是「所有玩家同樣看不到」，若玩法不允許隱藏危險，對敵人也呼叫 `isOccluded()` 顯示輪廓。

**仍未涵蓋**：等角菱形座標、真 3D 高度網格（見 §5，做法已寫但無程式）。
