## 1. 為什麼要改

現行 `RULE-SKILL-DOMINANCE` 是必過規則、套用所有遊戲：固定局數的種子 × 三級技巧 bot，看「技巧等級佔分數變異的比例」與「最強對次強的同種子勝率」。兩件事說明它不能當通用定義：

| 證據 | 量到什麼 | 說明了什麼 |
|---|---|---|
| GateLane | 技巧佔比 91%、勝率 88–93%，全過；但「只選數字大的門＋頭目戰追頭目」一條固定規則 30 局擊倒頭目 28 次、拿到 expert 平均分 62% | 級距來自最低一級是亂走；指標通過不代表有技巧深度 |
| 限時接龍（紙上試跑的最小模擬） | 技巧佔比 8–13%；種子佔比 52–57%；三級決策相同、只差手速時，同種子快的一方贏 89%，技巧佔比卻是 0.1% | 技巧佔比量的是「級距相對於題目難度差異有多大」，不是「同一題上技巧是否決定勝負」；題目難度差異大的遊戲一定低 |

接龍是知識庫自己的市場調查列出的第一大品類，排除標準也明寫保留。現行規則會把它擋下。

接龍那組數字只夠推翻舊指標的通用性，**不夠校準新門檻**：模擬裡的 expert 只解完 4.7% 的牌局，計分是仿製，每步耗時是假設值。

## 2. 原則

1. **問題通用，量法與門檻不通用。**「技巧是否決定結果」每款都要回答；怎麼量、多少算過，依遊戲結構而定，並且要有該結構的證據。
2. **能自動判定的才自動擋關。**「強者在同一題上是否顯著勝出」可以自動判定。「簡單打法離強者多近才算太淺」目前沒有跨遊戲的依據，交給人判定並留下理由。
3. **量測單位對齊實際賽制。**同題對戰的勝率不能替多人名次賽或跨題排行榜背書；產品怎麼決勝，就照那個方式量。
4. **工程規則不下法律結論。**規則與報告只稱「技巧證據」，不使用「合法」「技巧主導已證明」。各地區與賽制的法律判斷另行查證。

## 3. 共同資料格式：結果表

所有指標由一張表算出，表由測試程式重跑產生，不手填。

| 欄位 | 說明 |
|---|---|
| 題目 | 種子或關卡；確認用的題目不得用於調整策略 |
| 比較組 | 事先凍結的策略（或真人組）：名稱、程式雜湊、能看到的資訊、能力限制 |
| 結果 | 分數、是否完成、實際賽制下的名次 |
| 配對 | 兩兩同題的勝、平、敗與分差；平手算半勝並另列平手率 |
| 中繼資料 | 計分版本、題目抽樣方式、重跑指令、未量到的因素 |

確認集上失敗後若更換策略，必須另取一批確認用的題目。

## 4. 規則

| 規則 | 層級 | 適用 | 語意 |
|---|---|---|---|
| 技巧證據（新） | 必過 | 所有遊戲 | 交出與實際賽制對齊、可重跑的結果表；比較組、能看到的資訊、確認用題目都事先凍結。缺任何一項即不完整。擋的是「沒有證據」 |
| 排除純運氣（新） | 必過 | 所有遊戲 | 強策略對「合法的隨機策略」，同題配對的檢定要顯著（量法見 §9；原寫「單側信賴下界高於平手線」，已由 §9 取代） |
| 勝過簡單策略（新） | 必過 | 所有遊戲 | 強策略對「事先選定的簡單策略」，同題配對的檢定要顯著（量法見 §9）。主張決策技巧時，另報雙方每步耗時相同的結果 |
| 簡單策略的接近程度（新） | 必須量測，人工判定 | 所有遊戲 | 簡單策略拿到強者多少分數、完成率多少、多少題落在有意義的分差內。沒有通過線；在調校節點由人核准或退回，核准要寫理由。沒有可信的強者或可證的上限時標「無法判定」 |
| 執行雜訊曲線（新） | 必須量測 | 所有遊戲 | 同一策略逐級加延遲、誤差、漏看，報同題表現是否單調變差。速度與決策分開擾動 |
| 題目敏感度（新） | 必須量測 | 所有遊戲 | 題目佔分數變異的比例、強弱順序翻轉的比例、無解率；有隱藏資訊時另報「固定可見局面、依原分布重抽未知部分」的結果散布。用來選賽制與安排審查 |
| 現行技巧佔比與勝率 | 回歸警報 | 僅 SwarmDuel、TwinStrike、GateLane | 原門檻不變，標明「舊配方指標，不作跨品類或法律結論」。新遊戲不套用 |

**「簡單策略」的要求**：事先凍結；寫明它能看到的資訊、搜尋深度、記憶；不需要精準時機或瞄準就能照做。至少一條，建議兩到三條。它由誰挑仍可操弄，這點沒有解決（§6）。

**現行 `RULE-SKILL-BASELINE`（平均分比值）**：併入「簡單策略的接近程度」，不再有獨立門檻。

## 5. 關卡怎麼接

| 節點 | 變更 |
|---|---|
| N4 核心 | 產出改為「強策略、合法隨機策略、簡單策略」的定義與結果表工具；不再寫死 bot 檔名（細節隨結構描述另案定） |
| N5 調校 | 三條必過規則自動擋關。「接近程度」用迴圈既有的人工核准：沒有人核准就過不了這個節點；核准或退回都寫進紀錄 |
| N9 真人試玩 | 少量真人、每人多題、用難度相近但沒見過的題目；只用來檢查策略的強弱排序像不像真人，精度不足之處要寫明 |
| N10 發布 | 接近程度標為「未核准」或「無法判定」時，不得對外主張技巧深度 |

## 6. 討論紀錄與未解決的事

三方討論（Claude 主持並提案；Codex / GPT-6；Antigravity / Gemini 4 Argon），三輪。

| 議題 | 結果 |
|---|---|
| 新指標是否全部只觀測 | Claude 原主張是；Codex、Gemini 反對（報表齊全的純運氣遊戲會過關）。採用：要有硬關卡 |
| 硬關卡只比隨機策略夠不夠 | Codex 原主張夠；Gemini 指出動作類的隨機策略等於自殺，擋不住淺玩法。採用：再加「勝過簡單策略」 |
| 統一的勝率數字門檻 | Gemini 第一輪提出多個數字，因無跨遊戲校準而撤回。採用：只要求顯著高於平手線 |
| 深度沒過時自動擋關或只標記 | 未收斂。Gemini：自動擋在調校節點；Codex：標記並交人審。採用折衷：人工核准才能通過（§5） |
| 「勝過簡單策略」能否抓到 GateLane 的問題 | 主持人補充：不能。GateLane 的 expert 對那條規則同題全勝，這一關會通過；當初的警訊是分數接近程度。所以接近程度獨立成一條 |

未解決：

- 簡單策略與雜訊模型都由設計者選，仍可操弄；目前只要求事先凍結並公開。
- 所有新規則都沒有非動作類遊戲的實作證據。
- 隱藏資訊的量法需要解題程式來標記無解題，尚未實作。
- 小團隊拿不到大樣本的真人資料；N9 只做排序校驗。
- 討論中引用的美國判例與「北美現金賽判準」未經查證，不得寫入知識庫。

## 8. 落地順序（每步可獨立驗證）

1. 結果表工具：由現有 `dominance.mjs` 擴充，輸出逐題配對結果；現有三款的報告數字不得改變。

3. 現行兩條規則縮為現有三款的回歸警報；移除 N5 對 `RULE-SKILL-BASELINE` 的退回路由。
4. N5 加上「接近程度」的人工核准。
5. 知識庫 01 §4 改寫為方法說明；GateLane 的教訓改成註明來源的案例。

## 9. 量法定案（2026-11-11，落地第 1 步時補）

§4 原本寫「同題配對優勢的單側信賴下界要高於平手線」，當時沒有定算法；§4 現已改為轉引本節。圓桌討論（Codex、Gemini 各兩輪）後定案如下。

| 項目 | 定案 | 理由 |
|---|---|---|
| 檢定 | 對**分出勝負的題目**做精確的單側符號檢定：若兩個策略一樣強，分出勝負的題目裡出現這麼多勝場的機率有多小 | 結果有勝、平、敗三種值，不是二元資料；主持人原提案把「平手算半勝」的勝率套二項區間，兩方都指出是錯的。最保守的通用下界在 30 題時要七成以上勝率才過得了，實務上不可行 |
| 平手 | 不帶方向，不進檢定；但平手率、配對優勢（勝＋平手的一半，除以題數）一律報告 | 丟掉平手會讓「大量平手、少數勝」通過檢定。這種情況不另設門檻，列入「簡單策略的接近程度」的人工判定 |
| 多條簡單策略 | 強策略要勝過**每一條**事先凍結的簡單策略；不做多重比較修正；不得看了結果才挑一條 | 「全部成立」的判準本身不會放大誤判率 |
| 策略的亂數 | 由題目種子與策略決定，每題一個確定的結果（工具每一局都跑兩次並比對，不同就拒絕）；先不做每題重抽 | 兩方都同意這樣成立；重抽只降低雜訊，檢定單位仍是題目。需要時再加 |
| 隨機策略 | 在「合法而且會推進遊戲」的動作裡均勻抽，不是純亂按；動作集合與排除理由要寫明 | 純亂按在即時遊戲等於不玩，這條規則會形同虛設。它只是基本檢查，真正把關的是「勝過簡單策略」 |
| 效果量 | 勝平敗數、平手率、分差、分數比一律報告；不設門檻 | 沒有跨玩法的依據 |
| 固定題庫、手工關卡 | 全部跑完是普查：只報「在這個題庫上的結果」，不宣稱對未來題目的信賴下界 | 題目不是抽樣來的，檢定的前提不成立。**工具目前只支援由種子抽題**，這一項尚未實作 |
| 確認用題目 | 調校用與確認用分屬不同批次；確認模式把一批的完整身分寫進紀錄並凍結：遊戲、版本、策略程式的雜湊、題數、基準種子、門檻、判定、各組勝平敗，以及逐題結果的雜湊。已用過的批次只能原樣重跑；任何一項不同（改過策略或規則、換題數、換門檻）都必須用下一批。沒通過的批次也算用過。同一份紀錄不能換基準種子 | 只比對雜湊的話，同一批可以換題數重抽到通過（Codex 審查實測）。這只能讓重用留下痕跡，不能證明沒有人先看過 |
| 雜湊的範圍 | 策略檔、sim、量法工具本身，以及它們以相對路徑 import 的所有檔案（一路追到底）；報告列出檔案清單 | 策略常把實作放在別的檔案；只算入口檔的話，改實作不會換批次。改量法程式也會改變判定，所以一併納入。相依檔是用文字掃描找的，不是語法解析：計算出來的路徑、用檔案讀取載入的資料掃不到，要靠人對照清單 |
| 批次之間的重疊 | 各批用不同的序列產生；同一批內不重複；確認批次產生時直接跳過同題數調校批次裡的題目。不同確認批次之間不比對 | 題目種子只有 32 位元，不同序列只是「不太可能重疊」。確認批次之間偶爾共用一兩題，只會讓兩次確認稍微不獨立，不能用來重抽；而逐批比對在批次多時會把紀錄卡死（Codex 複審實測第 102 批與第 97 批重疊）。不同題數的調校批次不在排除範圍內 |
| 適用前提 | 題目由種子抽出、每題一局、分數是有限數值而且越高越好。分數不是有限數值、或大到無法計算平均與分差，就拒絕執行；有負分時不計算分數比 | 名次制、低分制、多人賽的勝負不能用分數相減判定，要另定比較方式，尚未支援 |

要進 `rules.json` 的數字只有兩個：顯著水準、最少題數。兩個都要標明「統計慣例，尚未跨玩法校準」。（已寫入 `RULE-SKILL-EVIDENCE`，泛用化步驟 4b；其他兩條必過規則引用它，不另寫數字。）

未收斂：Gemini 主張隨機策略每題重抽多次並設「最少有效題數」門檻；Codex 主張先不設。採用後者。
