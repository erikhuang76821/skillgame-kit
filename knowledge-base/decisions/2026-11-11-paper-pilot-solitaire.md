# 紙上試跑：限時接龍走一遍迴圈（三庫通用性檢查）

- **日期**：2026-11-11
- **狀態**：紀錄（尚未據此修改任何規則、卡片、節點）
- **目的**：三庫與迴圈目前只服務過三款即時動作遊戲（SwarmDuel、TwinStrike、GateLane）。用一款形態不同的題目，不寫程式，只看各節點實際發出的規則、測試、知識、資產，找出對既有形態的擬合。
- **相關**：[三庫分離＋迴圈工程](2026-11-10-libraries-and-loop.md)

## 1. 題目與做法

題目：**限時 Klondike 接龍**（同一副牌、限時、比總分）。選它的理由：知識庫自己的市場調查把接龍列為北美第一大品類（[02 §1](../02_market-and-legal.md)），而且排除標準明寫接龍因同牌序同種子而保留（[02 §4](../02_market-and-legal.md)）；形態上是離散決策、有蓋牌、沒有腳本化波次、以牌面與排版為主。

做法：寫一份假想 profile，對 N0–N11 每個節點呼叫 `buildContext`（與 `loop.mjs next` 相同的取用器），記錄發出的內容。沒有建立遊戲資料夾，所以「缺檔」類的結果只看它要求哪些檔。

重跑方式：`node shared/experiments/2026-11-11-paper-pilots/walk-nodes.mjs`（腳本與當時的輸出摘要在 [`shared/experiments/2026-11-11-paper-pilots/`](../../shared/experiments/2026-11-11-paper-pilots/README.md)）。

**限制**：這是一款題目的紙上判讀，沒有實作、沒有量測。下面標「預測」的項目都未經驗證。

## 2. 假想 profile：想填的值有一半不在詞彙裡

| 欄位 | 想填 | 詞彙是否接受 | 試跑用的代理值 |
|---|---|---|---|
| genre | solitaire（或 card） | ✗ | sort-puzzle |
| skillAxis | planning＋speed | speed ✗ | planning |
| renderer | dom（純 HTML/CSS） | ✗（只有 2d、3d） | 2d |
| artStyle | flat-vector / 排版 | ✗ | procedural |
| source、jurisdiction | original、TW／US-* | ✓ | — |

第一個發現在走迴圈之前就出現：想填的值不在詞彙裡。這時設計者有兩個選擇，都不好：**留空**（profile 驗證不要求這些欄位必填，但留空會讓取用變寬，見[試跑二 §9](2026-11-11-paper-pilot-pool-word.md)），或**填一個相近的代理值**。這次試跑選了代理值；`sort-puzzle` 等是我選的，不是唯一或最接近的選擇，換別的代理值結果可能不同。

## 3. 逐節點發現

分類：**誤用**＝發了不該發的東西；**缺漏**＝該有的沒有；**綁定**＝產出或工具寫死成某種形態；**可用**＝照用沒問題。

| 節點 | 分類 | 發現 |
|---|---|---|
| N0 立項 | 可用 | 排除標準卡正好涵蓋「牌戲排除、接龍保留」的邊界，法規卡適用 |
| N0 | 誤用 | 17 張卡有 5 張是廣告玩法（ad-funnel）的卡，原創題不需要；這些卡沒有標 source，被當成通用卡發出 |
| N0 | 誤用 | 列出 4 筆「可照配方重生」的資產，全是 TwinStrike 的：佔位美術、音效、**keysound**、BGM。資產檢索只看可否重用，不看品類與風格，也沒有依相關性排序 |
| N1 去隨機化 | 可用 | 去隨機化手法卡適用（洗牌由種子決定） |
| N1 | 缺漏 | 沒有任何卡處理**蓋牌（隱藏資訊）**與**無解牌局**。接龍的規則卡自己寫著「個別牌局本身可能無解」，但知識庫沒有「種子篩選、可解性檢查、發牌運氣怎麼量」的做法 |
| N2 規格 | 缺漏 | 最相關的知識拿不到：接龍、21 點、賓果等 **38 張規則卡放在 `SwarmDuel/knowledge/rules/`**，不在知識卡索引內，取用器撈不到；只能靠 03 的一張索引卡裡的連結間接找到 |
| N2 | 誤用 | 品類對應卡給接龍的唯一一句話是「節奏的判定窗用於塗記速度計分」，那是賓果的做法，套在接龍上不對 |
| N2 | 綁定 | 規格範本 §2「每 tick 1 byte」、§4「Tick 順序」、§9「Bot」是即時形態的寫法。限時接龍勉強能套（有計時、core 已支援選擇事件），不限時的解謎就套不上 |
| N3 起手 | 綁定 | 範本只有一份：Pixi＋節拍點擊示範。牌類可以整個用 DOM 做，但沒有對應的起手式，技術棧白名單也沒說純 DOM 算不算合規 |
| N3、N4、N6 | 誤用 | 地形風格套件的卡出現在三個節點（N6 的 15 張卡裡佔 5 張）；接龍沒有地形 |
| N4 sim | 可用 | 確定性 sim、重播驗分、`RULE-SIM-PURITY` 都適用 |
| N4 | 綁定 | 產出寫死 `game/tools/bots.mjs`。接龍的「分級玩家」更自然的做法是不同搜尋深度的 solver |
| N5 調校 | 誤用 | 五條難度曲線規則（必過）全部套用。一副牌一局，沒有腳本化段落，這些指標沒有對象。原因：規則寫的 `difficulty: scripted` 沒有被檢查（已另行確認） |
| N5 | 綁定 | 三張測試卡都要求 `bots.mjs`、`humanBots.mjs`、`playtest.mjs` 這些檔名 |
| N5 | 預測 | 技巧主導的「技巧佔分數變異 ≥ 門檻」對接龍可能不過（結果見 §7）：發牌難度與無解牌局會讓「種子」佔比很大。同種子對戰勝率那一項不受影響。**未量測**；若屬實，代表一個法規上明確保留、市場最大的品類會被現行必過規則擋下 |
| N6 美術 | 缺漏 | 沒有牌面、字型、排版、圖示的做法；資產類型也沒有這幾類 |
| N6 | 誤用 | 列出的共用資產是震動、衝擊波、粒子、地形塵土 |
| N6 | 缺漏 | 「知識缺口」只回報 `artStyle=procedural` 沒有卡，那是被迫填錯的值；真正的缺口（牌面美術）因為詞彙沒有這個值而報不出來 |
| N7 手感 | 綁定 | 產出寫死 `fx/feel.js`、`audio/sfx.js`；內容對牌類仍有用（發牌、翻牌的回饋），屬輕度 |
| N8 預算 | 綁定 | Draw Call 審查要求 `game/src/debug/drawCalls.js`（Pixi 專用）；純 DOM 遊戲沒有 draw call 這個概念。包體與禁 CDN 適用 |
| N9 試玩 | 綁定 | 節點名稱與測試卡是「真人對照 bot」 |
| N10 發布 | 誤用 | 全量規則＝把上面每個問題再套一次 |
| N11 回饋 | 可用 | 無內容，不受影響 |

## 4. 歸納：四種病因

1. **詞彙只長到做過的遊戲**。品類、技巧軸、渲染方式、美術風格都缺值；缺值時設計者只能填錯，之後的取用與缺口回報都跟著錯。
2. **「沒標」被當成「通用」**。許多卡只標了 `genre=*` 或沒標技巧軸、美術風格，於是地形、廣告玩法、節奏 keysound 會發給任何遊戲。標籤要表達的是「適用於誰」，現在多數卡沒有回答這個問題。
3. **量法寫進了產出與檔名**。節點要的是「技巧證據」「難度證據」，寫下來的卻是 `bots.mjs`、`playtest.mjs`、`drawCalls.js`。
4. **知識放在遊戲資料夾裡**。38 張規則卡是跨遊戲的調查成果，卻在 `SwarmDuel/knowledge/`，索引看不到。這與擬合方向相反：不是把單一遊戲的東西放進共用層，而是把共用的東西留在單一遊戲裡。

## 5. 試跑沒有發現問題的部分

- 迴圈的階段順序（立項 → 去隨機化 → 規格 → 起手 → 核心 → 調校 → 美術 → 手感 → 預算 → 試玩 → 發布 → 回饋）對接龍成立。
- 契約層成立：同種子、確定性 sim、輸入重播驗分、包體上限、禁 CDN、排除標準。
- 精髓七條、去隨機化手法、公平性模式卡的內容大多適用。
- core 的亂數、雜湊、重播驗證可直接用；選擇事件已有支援。

## 7. 補充量測：接龍的技巧佔比（驗證 N5 的預測）

為了檢查 §3 的 N5 預測，寫了一個最小的限時接龍模擬（抽 3 張、仿 Solitaire Cube 計分、300 秒），三級策略只看翻開的牌。腳本是 [`shared/experiments/2026-11-11-paper-pilots/klondike.mjs`](../../shared/experiments/2026-11-11-paper-pilots/README.md)；變異分解的算法和 `dominance.mjs` 相同。

| 情境 | 局數 | 技巧佔比 | 種子佔比 | 最強 vs 次強（同種子） |
|---|---|---|---|---|
| 只比決策（三級同速、無時間獎勵） | 300 | 8.0% | 57.0% | 61.2% |
| 決策＋速度（每步 2.5／1.5／0.9 秒、含時間獎勵） | 30 | 9.4% | 57.4% | 78.3% |
| 同上 | 300 | 12.5% | 51.5% | 68.5% |
| 只比速度（三級決策相同，只差每步秒數） | 300 | 0.1% | 99.1% | 89.2% |

決策＋速度情境的平均分：novice 691、intermediate 1,064、expert 1,338；各級分數標準差 405／737／879，比級距（約 300）大得多。

**結論**

1. **在這個模擬裡預測成立**：技巧佔比 8–13%，遠低於 `RULE-SKILL-DOMINANCE` 的門檻。這只說明「這個模擬＋這組弱策略」過不了，不能直接推論正式的接龍產品過不了。
2. **「只比速度」那一列說明問題出在指標，不只是策略太弱**：三級決策完全相同、只差手速，同種子下快的一方贏 89%，技巧佔比卻只有 0.1%。這個指標量的是「級距相對於題目難度差異有多大」，不是「同一題上技巧是否決定勝負」。推論（未在其他遊戲驗證）：題目難度差異越大，這個指標越低。
3. **同種子勝率比較接近「技巧是否決定結果」**，但它在 30 局時不穩（78% 對 300 局的 68%），而且會受分級策略強弱影響。
4. **這組策略裡，expert 和中級策略分不開**：「基礎堆 → 翻開蓋牌 → 出廢牌 → 翻牌堆」這條固定順序就是模擬裡的 intermediate，它以每步 1.5 秒拿到每步 0.9 秒的 expert 平均分的 79.6%。這個比較同時變了策略和速度，而且 expert 很弱，所以它說明的是「比較組沒寫好」，不能用來判斷 `RULE-SKILL-BASELINE`（該規則是 should 層級的警告，不是必過）在接龍是否合適。

**這個量測的侷限**

- expert 策略很弱：只解完 4.7% 的牌局。熟練的真人應該更高，但這次沒有量。更強的 expert 會拉高技巧佔比，但第 2 點不受影響。
- 每步秒數、未解完時的時間獎勵折算（依上基礎堆的張數比例）都是假設，官方公式未公開。
- 只有一款、一種計分。

**含意**：技巧主導這個「問題」對接龍仍然必答，但這次量測反駁了「把技巧佔分數變異當成所有形態的必過指標」。後續的處理見[技巧證據的規則重構](2026-11-11-skill-evidence.md)。

## 8. 這份試跑本身的侷限

- 只試了一款。接龍暴露的是「離散決策＋隱藏資訊＋牌面美術」這一類的問題；物理瞄準、文字、對戰可能各有不同的故障。
- 沒有反向驗證：修正後要確認三款既有遊戲拿到的內容不變。
- 判讀由一人完成，「誤用」「缺漏」的歸類帶有主觀。
