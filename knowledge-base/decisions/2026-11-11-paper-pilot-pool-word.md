# 紙上試跑（二）：撞球解球與限時拼字，以及三次試跑的比較

- **日期**：2026-11-11
- **狀態**：紀錄（尚未據此修改任何規則、卡片、節點）。2026-11-11 經 Codex 審查後修正過措辭與數字口徑，見 §9
- **目的**：企劃決定（[通用化待辦 §3 D1](2026-11-11-generality-backlog.md)）要優先支援牌類／盤面、物理瞄準、文字／邏輯解謎。接龍已試跑過（[試跑一](2026-11-11-paper-pilot-solitaire.md)），這裡補另外兩類，並在定 profile 的結構欄位前比較三次的結果。
- **做法**：與試跑一相同，用假想 profile 對 N0–N11 呼叫取用器。腳本與當時輸出在 [`shared/experiments/2026-11-11-paper-pilots/`](../../shared/experiments/2026-11-11-paper-pilots/README.md)：`node shared/experiments/2026-11-11-paper-pilots/walk-nodes.mjs pool`（或 `word`、`solitaire`）。
- **限制**：紙上判讀，沒有實作。撞球引用的量測是知識庫既有的範例數據，不是這次量的；拼字完全沒有量測。

## 1. 兩個題目

| | 撞球解球 | 限時拼字 |
|---|---|---|
| 玩法 | 同一組球型，一次一桿（角度＋力道），固定桿數比進球分 | 同一個種子的字母盤，限時找出合法單字，依字長計分 |
| 為什麼選 | 知識庫已有確定性物理的配方與範例，是「已有準備但沒做過」的一類 | 和現有形態差最遠：技巧是字彙量；需要字典；以排版為主 |
| 想填的 profile | genre=physics、skillAxis=aim＋planning、renderer=2d、artStyle=realistic | genre=word、skillAxis=vocabulary＋speed、renderer=dom、artStyle=typographic |
| 詞彙是否接受 | **全部接受** | genre、兩個技巧軸、renderer、artStyle 都不接受 |
| 試跑用的代理值 | — | block-puzzle、planning＋reaction、2d、procedural（我選的，不是唯一或最接近的選擇；也可以留空） |

## 2. 最重要的發現：不同遊戲拿到的知識高度重疊

把六個 profile（三款既有遊戲＋三次試跑的代理 profile）在 12 個節點拿到的知識卡兩兩比較。算法：逐節點比對卡片 ID，把 12 個節點的交集數加總，除以聯集數加總。只看「拿到哪些卡」，不看排序與全文：

| | 接龍 | 撞球 | 拼字 | GateLane | TwinStrike | SwarmDuel |
|---|---|---|---|---|---|---|
| 接龍 | — | 96% | 100% | 84% | 97% | 98% |
| 撞球 | 96% | — | 96% | 83% | 94% | 94% |
| 拼字 | 100% | 96% | — | 84% | 97% | 98% |

- 三次試跑各有 139 個「節點 × 卡」的出現次數；不同的卡是接龍 70 張、拼字 70 張、撞球 71 張。**接龍和拼字逐節點拿到的卡 ID 完全相同**。撞球多的那一張是物理配方卡，它出現在 N2、N3、N4；在 N4 還因為預算，擠掉了三張技術卡。
- 三次試跑適用的規則 ID 與測試 ID 清單**完全相同**。
- GateLane 和其他遊戲的差別幾乎全部來自 11 張廣告玩法改編的卡。

原因：103 張卡裡有 89 張標 `genre=*`、90 張沒有標技巧軸。標了具體品類的只有 lane-shooter 11 張、rhythm 2 張、physics 1 張。

含意：取用器確實會依 profile 改變輸出（物理卡進了撞球的包，GateLane 多拿到來源限定的卡，預算也會擠卡），但**以目前的卡片標記和節點查詢，不同遊戲拿到的內容高度重疊**。原因有兩個：多數卡沒有回答「適用於誰」；節點的查詢本身也很寬（§9）。所以**只擴充詞彙不足以改善**：新值能讓 profile 填得進去、讓缺口回報變準，但沒有卡片標它們、查詢也沒變的話，拿到的專屬內容不會增加。這個結論只對這次的代理 profile 成立。

## 3. 撞球：逐節點

| 節點 | 分類 | 發現 |
|---|---|---|
| N0 立項 | 可用 | profile 填得進去；法規卡適用 |
| N0、N6 | 誤用 | N0 列出的可重生資產是 TwinStrike 的佔位美術、音效、keysound、BGM；N6 列出的是共用範本的震動、暗角、衝擊波、粒子與地形塵土。兩處都沒有依相關性排序 |
| N2–N4 | 可用 | 拿到物理配方卡：整數子像素、4096 方向表、一桿＝一個選擇事件、防穿透、球型公平（只接受有無遮擋進袋線的擺位）。範本有 `core/physics.js` 與 `examples/billiards/` |
| N2 | 缺漏 | 撞球的規則卡（Pool Payday、台灣撞球）在 `SwarmDuel/knowledge/rules/`，撈不到 |
| N4 | 綁定（輕） | 產出要 `bots.mjs`；撞球範例本來就有 bot，這裡沒有問題 |
| N5 | 誤用 | 五條難度曲線規則套用。固定桿數的解球沒有腳本化段落 |
| N5 | **證據** | 物理配方卡記錄了範例從 v1 到 v7 的調整。v1–v3 主要在修正確性（慢速球不停、碰撞法線、先判進袋）；v4–v7 才是計分、桿數（8 → 16 → 24）、球數（11 → 14）的取捨，而且每一版都對照技巧佔比與勝率來判斷。原頁寫 v6「仍貼著門檻」，v7 四組種子是 75–81%，結論寫「撞球類天生更吃球型」。**物理範例後期的調校明顯參照了技巧佔比門檻** |
| N6 | 缺漏 | 回報 `artStyle=realistic` 沒有任何卡。缺口回報在這裡是準的，因為 profile 填的是真的值 |
| N8 | 可用 | Pixi、Draw Call、包體都適用 |
| N9、N10 | 同接龍 | 節點名稱與全量規則的問題相同 |

**小結**：撞球是三次裡最順的。詞彙、配方、範本、core 模組都有。問題集中在兩處：難度曲線規則不該套用；技巧佔比門檻已經在影響它的設計。

## 4. 拼字：逐節點

| 節點 | 分類 | 發現 |
|---|---|---|
| N0 | 綁定 | profile 五個值填不進去，只能填錯 |
| N1 去隨機化 | 可用 | 字母盤由種子產生，適用 |
| N1 | 缺漏 | 沒有「題目可解性」的做法：某些字母盤能拼的字很少。和接龍的無解牌局是同一類問題 |
| N2 | 缺漏 | 規則卡（Word Cube 2）在 SwarmDuel 資料夾，撈不到。品類對應卡沒有文字類 |
| N2 | 缺漏 | **字典**沒有任何知識：來源與授權、語言（繁體中文的「詞」與英文單字是不同的問題）、收錄標準、版本要不要進重播驗證 |
| N2 | 缺漏 | **場外查詢**：Word Cube 2 的規則卡提到「無法完全防外部查詢工具」與暫停不停表，但那張卡不在共用索引裡，取用器拿不到；共用知識庫的防作弊只談巨集與反應時間，沒有「技巧是知識」時的完整做法 |
| N3 | 綁定 | 沒有純 DOM 的起手式 |
| N4 | 可用 | sim、重播驗分適用（輸入是「選了哪些格子」的步驟） |
| N4、N5 | 綁定 | 產出與測試卡要 bot 檔。拼字的分級策略自然是「不同大小的字典」，不是操作誤差 |
| N5 | 誤用 | 五條難度曲線規則套用；一盤一局沒有段落 |
| N6 | 缺漏 | 沒有字型、排版的做法；字型授權與字型檔大小沒有任何規則或知識 |
| N6 | 缺漏 | 資產類型沒有「資料」（字典）。字型目前是以 `kind=ui` 登錄的（資產索引裡有一筆 `swarmduel.ui.font.pixelify`），沒有獨立的字型類型，也沒有適合文字遊戲的取用方式。字典也是要登錄來源、可重現的資產 |
| N8 | 可用但有新問題 | 包體規則適用，而且是真的限制：中文字型與字典都很大。Draw Call 審查不適用 |
| N9 | 綁定 | 「對照 bot」；另外真人的字彙量差異很大，少量樣本更難代表 |

**小結**：拼字帶出兩個前兩次沒有的題目：**資料型資產**（字典、字型）和**以知識為技巧**（分級、作弊、真人取樣都不同）。

## 5. 三次試跑的比較

| 面向 | 接龍 | 撞球 | 拼字 |
|---|---|---|---|
| profile 填得進去 | ✗ | ✓ | ✗ |
| 有品類配方 | ✗（一句話，而且寫錯） | ✓ | ✗ |
| 有範本或範例 | ✗ | ✓ | ✗ |
| 輸入形式 | 一步一個動作 | 一桿一個選擇 | 一步一個選取 |
| 是否即時 | 限時，但動作離散 | 不限時（按桿） | 限時，動作離散 |
| 挑戰來源 | 一副牌 | 一組球型 | 一個字母盤 |
| 隱藏資訊 | 有（蓋牌） | 無 | 無 |
| 題目好壞差異 | 很大（無解牌局） | 大（球型） | 大（可拼的字數） |
| 分級策略的自然形式 | 搜尋深度 | 瞄準誤差 | 字典大小 |
| 難度曲線規則適用 | ✗ | ✗ | ✗ |
| 特有的資產 | 牌面 | 球、檯面 | 字典、字型 |

**三次共通**

1. 三款都**不是**「一局之內有腳本化段落」的遊戲，五條難度曲線規則都不該套用。現有三款即時動作遊戲才是這種結構。
2. 三款的題目好壞差異都大。「題目本身的難度差多少」「題目是否可解或公平」在三款都是核心問題，知識庫只有撞球寫了做法。
3. 三款的輸入都是離散的步驟或選擇，不是每 tick 的連續輸入。core 的選擇事件已經能表達撞球；接龍與拼字需要確認。
4. 三款的分級策略都不是「操作誤差不同的 bot」一種形式。
5. 規則卡都在 SwarmDuel 資料夾裡。

## 6. 對結構欄位（待辦 C2）的含意

三次試跑裡，讓規則該不該套用產生差別的只有下面幾件事。欄位名稱與取值採用 Codex 審查後的建議（§9）：布林值比單選清楚，也避開和既有 `source` facet 混淆的「挑戰來源」。

| 候選欄位 | 取值 | 哪些規則或節點依它判斷 | 證據 |
|---|---|---|---|
| `scriptedProgression` | 是／否：一局之內有沒有可量的腳本化段落 | `RULE-CURVE-TREND`、`-LINEARITY`、`-PEAKS`、`-CLIFF`、`-FLOW` 只適用「是」；相關的文件與報告要求（`gdd/07`、試玩報告）也要跟著 | 三次試跑 N5 |
| `playerInputMode` | 連續／離散：玩家的輸入形式（不是 sim 內部有沒有 tick） | 目前沒有對應的規則；先用於 N2、N4 的範本與輸入知識的取用 | 三次試跑 N2、N4 |
| `hiddenInformation` | 是／否 | 目前沒有對應的規則；用於選題目公平性的證據 | 接龍 |
| 渲染方式 | 現有的 2d、3d，加 dom | `RULE-DRAWCALL-2D`、`RULE-DRAWCALL-3D`、`RULE-TEMPLATE-LEFTOVER`；起手式 | 接龍、拼字 N3、N8 |

「逐關」三次試跑都沒有涵蓋（邏輯解謎才是）。沒有證據，先不定義，連取值都等試跑後再加。

「是否限時」這次**暫不加入**：接龍和拼字限時、撞球不限時，三者該套用的現有規則沒有因此不同。但這次沒有檢查計時、防場外查詢、延遲公平這些可能和限時有關的規則，所以不能說輸入形式已經取代了時間屬性。

技巧軸、品類、美術風格仍然只用來檢索知識與資產，不用來判斷規則適用。技巧類規則（`RULE-SKILL-DOMINANCE`、`RULE-SKILL-BASELINE`）不靠這幾個欄位宣告不適用，照[技巧證據的決策](2026-11-11-skill-evidence.md)另行處理。

## 8. 侷限

- 仍然只是紙上判讀，歸類由一人完成。
- 邏輯解謎（逐關、不限時）沒有試跑；它可能是和現有結構差最遠的一類。
- 撞球的數據來自知識庫既有紀錄，量法是舊的技巧佔比；依[技巧證據的決策](2026-11-11-skill-evidence.md)之後要用新的量法重看。
- 卡片重疊比例只算「拿到哪些卡」，沒有算排序與預算裁切後的差異。

## 9. Codex 審查（2026-11-11）後的更正與補充

**更正**（已改進本文與試跑一）

- 「必須填錯值才能通過驗證」不成立：profile 不要求這些欄位必填，可以留空。代理值是作者選的。
- 139 是「節點 × 卡」的出現次數，不是 139 張不同的卡；重疊比例的算法補寫在 §2。
- 撞球 N6 的資產敘述原本把 N0 與 N6 混在一起。
- 接龍的固定順序策略就是模擬裡的 intermediate，而且和 expert 的速度不同；不能用來判斷基準策略規則。
- 字型有登錄的先例（`kind=ui`）；場外查詢在未索引的規則卡裡有提到。
- 多處措辭說得太滿：「取用器只依節點取用」「只擴充詞彙沒有用」「七個版本都為了過門檻」「是否即時不必成欄」。
